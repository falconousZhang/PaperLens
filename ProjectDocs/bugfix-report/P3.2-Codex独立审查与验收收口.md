## 发现与修复

### 1. 华为云鉴权密钥被掩码

配置中的 `embedding_api_key` 类型为 Pydantic `SecretStr`。初版直接将对象格式化进 Authorization Header，实际发送值是 `Bearer **********`，测试因手工传入普通字符串而未覆盖真实配置路径。

修复后统一解析 `str | SecretStr`，对 SecretStr 调用 `get_secret_value()`，并新增从全局 Settings 注入 sentinel 密钥、捕获真实 Header 的测试。错误文本和任务公开错误均不包含密钥。

### 2. 外部推理跨越数据库事务

初版在 SQLAlchemy 隐式事务仍打开时调用 Embedding 和 LLM，可能造成长事务、连接池占用和外部超时后的复杂回滚。

修复后将流程拆为：加载最小 Evidence 候选 → 结束只读事务 → 完成全部 Embedding/LLM 与解析 → 重新取得任务 → 在一个最终事务中写入全部 ReviewResult、ReviewFinding、FindingEvidence 和 SUCCEEDED。外部调用前后均有事务边界守卫。

### 3. 华为适配器防御与连接复用不足

初版每个 batch 新建 httpx.Client，且非对象 JSON、非对象 data item、布尔 index、非法 base URL/model/timeout/batch_size 等输入可能产生不一致异常。

修复后一次 `embed()` 复用一个 httpx.Client，强制绝对 HTTPS URL、非空模型、正数超时和正整数 batch；严格校验响应对象、data item、index、数量、顺序、向量维度与有限数值。任一后续 batch 失败会丢弃本次全部结果，错误不包含完整响应体。

### 4. 中文语义排序失效

初版 Mock tokenizer 仅按空格切分，中文论文句子通常无空格，维度 query 与 Evidence 很难共享词项。

修复后英文保留字母数字 token，中文生成单字和双字 token；测试证明中英文相关词都会改变余弦排序，同时保持跨实例确定性。

### 5. 检索层职责与边界校验

初版将 SQL 查询、外部向量调用和排序耦合，并重复查询 Evidence ID；对 `top_k <= 0`、布尔 Top-K、空 dimensions、返回数量异常等缺少完整防御。

修复后以 `EvidenceCandidate` 分离数据库候选加载和纯排序/外部调用，去除重复列，严格验证维度、Top-K、向量数量和分数；稳定排序规则为 similarity 降序，再按 page_number、created_at、id 升序。

### 6. 工厂层次与文档真实性

默认 Embedding 工厂从 review_service 的私有函数迁至 embedding_client 的公开 `get_embedding_client()`，供 API 依赖注入和服务显式调用。README、架构、API 契约、SystemDesign、SDD、Sprint、实施状态和进度文档均已区分：P3.2 当前是任务内即时精确余弦检索，不是 FAISS/pgvector 持久化索引。

## 新增风险测试

- SecretStr 配置路径发送真实 Bearer token，而不是掩码。
- 非 HTTPS、空模型、零/布尔 batch、零 timeout 均被拒绝。
- 非对象响应、非对象 data item、布尔 index、非法向量统一失败。
- 后续 batch 返回 503 时不返回前序部分结果，也不泄漏响应体。
- Evidence 首次向量化与维度 query 向量化分别失败时，任务均为 FAILED。
- 上述失败路径中 ReviewResult、ReviewFinding、FindingEvidence 均为 0。
- 中文相关词可稳定改变检索排序。
