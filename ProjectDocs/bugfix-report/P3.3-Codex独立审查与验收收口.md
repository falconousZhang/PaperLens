## 3. 独立审查发现

1. **歧义 choice 被接受**：初版只拒绝重复 `index=0`，会忽略额外 `index=1` 或重复的非零 index，并继续使用 index 0，违反“当前未请求多 choice，歧义必须失败”的契约。
2. **直接构造校验不完整**：base URL、model、API Key 的错误类型可能触发 AttributeError；NaN、Infinity、超出 Settings 上界的 timeout/token 仍可进入底层 httpx。
3. **URL 边界不够明确**：只校验 HTTPS/host，仍接受带 userinfo、query 或 fragment 的 base URL，容易形成含义不清的部署配置。
4. **messages 类型错误不统一**：非可迭代对象会泄漏 TypeError，tuple 又会被当作合法输入；没有严格兑现“必须是非空列表”。
5. **未知完成原因回显上游值**：未知 `finish_reason` 的原值进入 LLMError，不符合错误最小披露原则。
6. **缺少真实业务集成覆盖**：只有客户端级 MockTransport 测试，没有证明 Huawei 响应能经过 review_service 的严格 JSON 解析、Evidence 绑定和最终原子写入。
7. **缺少首维/第二维失败覆盖**：没有用 HuaweiMaaSLLMClient 本身验证任一维失败后三类结果表均为 0。
8. **缺少 transport 事务断言**：没有在 Huawei transport 实际调用点确认 SQLAlchemy 审阅会话不持有活动事务。
9. **文档状态与计数失真**：README、API 契约和多份 ProjectDocs 仍称 P3.3 为规划态；配置项实际是 6 个而不是 5 个；路由数误报为 16。

## 4. Codex 直接修正

### 4.1 生产代码

- 为 base URL、model、API Key、timeout、max tokens 和 transport 增加稳定的 LLMError 类型校验。
- timeout 统一限制为有限数值 `1～600`，max completion tokens 限制为整数 `1～16384`，与 Settings 一致。
- base URL 拒绝凭据、query 和 fragment，保留固定 host 与 `/chat/completions` 安全相对路径。
- messages 必须是非空 list；每项仍严格限制 role/content，且不原地修改调用方对象。
- 对全部 choice 先校验合法、非重复 index；只接受唯一的 `index=0`，任何多 choice 或重复 index 都失败。
- 未知 finish_reason 只返回固定安全错误，不回显上游值；底层 HTTP/JSON 异常使用领域错误收口。
- 清理 llm_client.py 和 review_service.py 中的无效导入。

### 4.2 测试

- 客户端/工厂定向集从 55 增至 70，新增 URL/payload、错误类型、user info/query/fragment、NaN/Infinity/上界、非列表 messages、多 choice/重复非零 index 和错误回显测试。
- 新增 3 项 PostgreSQL API 集成用例：
  - Huawei MockTransport 两个维度成功，严格解析后产生 2 个 ReviewResult、2 个 Finding 和 2 个 Evidence 关联。
  - 首个 dimension 返回 `finish_reason=length` 时任务 FAILED，三类结果表均为 0。
  - 第二个 dimension 失败时同样整批回滚，不保留第一个维度结果。
- transport 在每次真实 handle_request 调用时记录审阅 Session 的 `in_transaction()`，最终均为 False。

### 4.3 文档

- 校准 README、环境变量模板、架构、API 契约、安全设计、实施状态、进度文档和相关 ProjectDocs。
- `.env.example` 的 LLM/Embedding Key 只保留空变量名，不放真实或看似真实的值。
- 明确默认仍为 Mock；HuaweiMaaSLLMClient 已实现但用户账号、区域、模型质量、真实网络和费用尚未验收。

## 6. 当前边界与下一阶段

P3.3 完成的是可部署适配代码、严格离线契约测试和完整审阅任务集成，不等价于真实华为云服务已经开通。当前仍不支持流式、自动重试、工具调用、联网搜索、多供应商路由或持久化向量索引。

下一阶段 P3.4 应只实现审阅结果前端与完整任务交互：`/papers/:id/review`、任务创建/恢复/轮询、维度结果与 Finding 筛选、Evidence 深链到现有 PaperDetail 高亮。P3.5 再实现注册登录、令牌生命周期、真实用户隔离和 USER/ADMIN RBAC。
