## 3. 独立审查发现

1. **重新审阅隐藏旧结果**：结果选择直接使用最新 REVIEW task；当最新任务仍在 PENDING/RUNNING 或已经 FAILED/CANCELLED 时，上一轮成功结果会消失，违反“新任务成功前继续显示旧结果”。
2. **轮询错误入口不可见**：轮询网络失败后同时清空 `activeTask`，而错误和重试按钮位于 `v-if="activeTask"` 内，导致用户看不到错误，也无法点击“重试轮询”。
3. **轮询终态未同步任务历史**：GET task 返回 FAILED/CANCELLED 时没有回写 tasks，失败状态可能仍按旧 RUNNING 数据计算，终态提示丢失。
4. **进度未限制范围**：API 异常值可直接进入 CSS width、文本和 aria-valuenow，未满足 0～100 的可访问性边界。
5. **成功后的刷新失败被静默吞掉**：任务 SUCCEEDED 后 listTasks/listReviews 失败时没有任何提示，页面会停在陈旧结果或空状态。
6. **并发与路由边界仍有缺口**：setInterval 允许慢请求重叠；创建任务响应没有 generation 守卫，旧论文请求可能覆盖新 paper id 页面。
7. **数组 Evidence query 没有可见提示**：虽然没有错误调用页面 API，但提示被清空，不符合未知/数组 query 的可见告警要求。
8. **前端类型不够严格**：TaskDetail/TaskCreateResponse 的 task_type 和 Finding.verification_status 使用宽泛 string，没有与后端枚举对齐。
9. **文档未按提示词同步**：README、SDD design/07、design/10、Sprint 等仍把 P05 写成 PLANNED；systemDesign/07 还出现损坏状态字符，测试数量停留在 39。

## 4. Codex 直接修正

### 4.1 生产代码

- 结果选择改为遍历 tasks 倒序，取最新且已有 ReviewResult 的 task_id；tasks 暂无匹配时再按 ReviewResult.created_at 降级。
- 活动或失败的新任务不再隐藏旧结果；最新任务成功但无新结果时继续显示旧结果并提供不一致提示和重新加载入口。
- 轮询错误保留 activeTask/activeTaskId，使错误和重试按钮可见；重试前清理旧 timer。
- 每次轮询回写 tasks；终态停止 timer，FAILED/CANCELLED 能立即进入安全错误状态。
- 进度统一钳制到 0～100，并同时用于宽度、文本和 aria-valuenow。
- 成功后的结果刷新失败显示“任务已完成，但刷新审阅结果失败”，不再静默吞错。
- 单个 timer 内增加请求互斥；创建响应增加 request generation 与 paper id 校验；路由变化重置表单、筛选、错误和活动任务状态。
- PaperDetail 对数组 query 显示“未找到对应证据”，不调用无关页面 API。
- 新增 TaskType、VerificationStatus 联合类型，并收紧相关响应字段。

### 4.2 回归测试

在码道 39 项基础上新增 6 项 ReviewResultView 回归，并增强数组 query 断言：

- 活动重新审阅任务保留上一轮成功结果。
- 最新失败任务保留上一轮成功结果。
- 轮询返回 FAILED 后立即显示失败状态。
- 进度异常值按 0～100 显示并保持可访问属性一致。
- SUCCEEDED 后刷新失败显示可恢复错误。
- paper id 变化后旧请求不得覆盖新论文页面。
- 轮询网络错误必须可见，点击重试后不叠加 timer。
- 数组 Evidence query 必须显示可见提示且不调用 getPage。
