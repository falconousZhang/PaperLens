## 2. 主要发现

1. config 与 Compose 存在硬编码 JWT fallback；算法和 TTL 缺合理上界，cookie Secure 被硬编码关闭。
2. access token 写入 localStorage；应用启动不依赖 HttpOnly refresh bootstrap。
3. access 鉴权只查 User，不查 sid/AuthSession，导致 logout、logout-all、改密和重置后旧 access 仍有效。
4. refresh 查询排除 revoked 行，旧 token 重放无法识别 family；replaced_by 未写入，缺少行锁，并发轮换可重复成功。
5. 禁用、锁定、邮箱不存在返回不同状态/文案；不存在账号调用新 Argon2 hash 而非 dummy verify。
6. 默认 PasswordResetNotifier 把明文 reset token 写入日志；reset 并发消费无行锁。
7. logout 不要求 access；401 缺少 `WWW-Authenticate: Bearer`；注册/登录响应缺 UserPublic/status/expires_in。
8. AuthSession/reset token hash 无唯一索引；业务 user_id 外键使用 CASCADE，删除用户可级联清空论文。
9. CLI 对已是 ADMIN 的用户提前返回，导致之后显式 `--claim-legacy-data` 无效。
10. 码道未按 AGENTS.md 同步 01～08、SDD、Sprint 和 bugfix report，多处仍声称认证未实现。

## 3. 直接修正

- JWT secret 改为必填 SecretStr，至少 32 字节；固定 HS256，必需 claims 全校验；Compose 使用必填变量，本地随机 secret 只写被忽略 `.env`。
- access/User 只存前端内存；refresh 只由 HttpOnly cookie 管理；并发 401 使用共享 single-flight，每请求最多重放一次，auth refresh 不递归。
- 增加 AuthContext，JWT 后强制查询 sid、session 撤销/过期、User 状态/锁定；所有 401 带 Bearer challenge。
- refresh 使用 token_hash 唯一查找和 `FOR UPDATE`，轮换写 replaced_by；重放在事务内撤销整个 family。
- 登录状态统一 401 文案并走 dummy Argon2；失败计数通过用户行锁串行化。
- NullPasswordResetNotifier 不联网、不记录 token；测试使用 capture fake；reset 单次消费和行锁。
- logout 依据当前 AuthContext 撤销 family；logout-all、改密、重置撤销全部 session。
- 005 在不 downgrade 开发库的前提下无损纠正 004：legacy password_hash nullable、两个 token_hash 唯一索引、有效期索引、四类业务资源和认证表 RESTRICT 外键。
- CLI 已支持“账号已是 ADMIN 后再显式 claim”，四类资源在单事务迁移。
- 前端补 safe redirect、状态展示、失败清理与 Unicode code point 密码长度；改密失败保留当前会话。
