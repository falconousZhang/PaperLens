# P4.1 Codex 独立审查与指标完整性验收收口

## 审查结论

码道 P4.1 初版不能验收。其 37 项定向测试全部通过，但没有断言后台任务最终状态；真实代码在查询来源后必然出现活动读事务，随后主动抛错，因此任务只能进入 FAILED。Codex 已在用户授权范围内直接修正，并完成独立全量验收。

## 主要问题

| 级别 | 问题 | 影响 |
|------|------|------|
| 严重 | 正常 SELECT 自动开启事务，却被当作“提取期间持有事务” | 所有指标后台任务必然失败 |
| 严重 | MetricRecord 可同时无来源，表格行/Evidence 可跨论文伪造 | 公开指标不可追溯 |
| 高 | 无 Checkpoint 证据保存 null；按宽松子串匹配 | 不符合 UNKNOWN 契约并可能误判 |
| 高 | 任意行首文本同时被当作模型和数据集 | 结构化字段系统性失真 |
| 高 | metric task 复用 REVIEW options；查询忽略未知参数 | API schema 不可区分且不严格 |
| 高 | 活动任务先查后写，无数据库唯一约束 | 并发请求可创建重复任务 |
| 高 | 测试未覆盖终态、来源、原子失败、ADMIN/USER 隔离和数据库约束 | 通过数字不能证明功能可用 |

## 修正内容

1. 读取表格/Evidence 为不可变快照，结束读事务后执行纯 Python 提取；写入阶段重新加锁并校验 task/paper/user。
2. 成功记录与 SUCCEEDED 同一事务提交；任一候选或写入失败整批回滚，任务只保存固定安全错误。
3. 每条候选必须且只能绑定表格行或 Evidence，校验来源存在、属于同一论文且表格行号有效。
4. 百分号统一为 0～1；非百分比指标允许有限负数；拒绝非有限值、范围和均值±误差。
5. 模型/数据集只从明确的 Model/Method 与 Dataset/Data 等列提取；不能可靠判断时为 null。
6. Checkpoint 使用完整关键词；冲突或无证据均为 UNKNOWN，绝不按数值最大猜测。
7. task_type 使用判别 union；metric options 只能为空；列表查询模型拒绝未知字段并限制分页。
8. 公开 API 联查 task、paper、user 和来源；跨用户详情为 404，ADMIN 不默认越权。
9. 新增 007，在不编辑已应用 006 的前提下补来源 FK RESTRICT、有限数值、来源二选一、Checkpoint 非空、task_type 与活动任务部分唯一索引。
