## 码道初版问题

1. Evidence 来源只显示“查看证据”文字，没有生成论文详情 Evidence query 深链。
2. 表格来源没有显示 `table_id` 和明确的 0-based `row_index`，`raw_text` 完全不可见。
3. 双来源异常结构优先猜测 Evidence，违反异常来源统一降级要求。
4. 没有成功任务时仍调用未携带 `task_id` 的指标列表接口，存在混合历史结果风险。
5. 历史任务下拉包含 RUNNING/FAILED 等非成功任务，用户可切换到没有稳定结果的任务。
6. 筛选结果为 0 后整个筛选栏消失，用户无法清空筛选。
7. 筛选、翻页和任务切换共用 route generation，没有独立请求序号，慢旧响应可能覆盖新目标。
8. 409 活动任务创建竞争只显示错误，没有重新加载服务端真实活动任务。
9. `TaskCreateRequest` 没有实现 REVIEW/METRIC_EXTRACTION 可区分 union，指标 API body、参数边界和受保护路由缺少直接测试。
10. systemDesign、SDD 和 Sprint 多处仍把 P4/P06 写成“规划/未开始”，与代码和自报完成状态矛盾。

## 直接修正

- 指标 API 请求类型改为 REVIEW/METRIC_EXTRACTION 判别联合；指标创建复用统一 `createTask`，分页参数限制为有效整数和 1～100。
- 页面只选择 `SUCCEEDED` 指标任务；没有成功任务时不查询指标；所有指标列表请求强制携带选定 `task_id`。
- 为指标查询增加独立 request id，并同时核对 route paper id、selected task id 和 generation，阻止连续交互的旧响应回写。
- Evidence 来源生成 `{name:'paper-detail', query:{evidence:evidence_id}}`；表格来源显示 ID 和 0-based 行号；双来源、无来源和非法行号统一降级。
- 显示规范百分比值和原始存储值；所有记录可用原生 `details` 展开 `raw_text`，只使用 Vue 文本插值。
- 筛选零结果时保留筛选栏和清空按钮；成功无结果、无任务、活动任务和失败任务分别展示真实状态。
- 409 创建竞争自动重新加载活动任务；未知任务上下文或状态停止轮询并显示可恢复错误。
- 新增 API/路由契约测试，补历史成功范围、零结果筛选、旧响应、409、异常来源、XSS 文本和论文详情入口断言。
- 按项目工作流同步 systemDesign 01～08、SDD spec/tasks/design 和两个相关 Sprint。
