# P4.3 真实 GLM 审阅 JSON 围栏兼容修复

## 现象

用户登录后对 BVG.pdf 发起真实审阅，页面最终显示“审阅生成失败，请稍后重试”。任务安全进入 FAILED，进度 10，三类审阅结果表均未留下该任务数据。

## 根因

华为云请求与鉴权均成功，GLM-5.2 返回 `finish_reason=stop`，但将完整单一 JSON 包在标准 `json` Markdown 围栏内。旧解析器明确拒绝任何围栏，因此在 `parse_llm_output` 阶段失败。华为 MaaS V2 公开契约未列出 `response_format=json_object`，不能依赖未声明的结构化输出参数。

排查还发现 Docker 开发配置的 `PAPERLENS_DEBUG=true` 会通过 SQLAlchemy `echo=settings.debug` 把论文表格原文和 SQL 绑定参数写入日志，违反既有日志脱敏设计。

## 修正

- 只在整段响应恰好由单层标准 `json`/`JSON`/无语言围栏构成时解包。
- 围栏前后附文、非 JSON 语言、嵌套/多个围栏和非标准同行围栏继续失败。
- 解包后仍执行原有 JSON object、Pydantic extra-forbid、类型、枚举、维度、长度和 Evidence alias 校验。
- 不记录模型正文、不自动重试，不改变 HuaweiMaaSLLMClient 的 HTTPS/Bearer/finish_reason 边界。
- SQLAlchemy engine 固定 `echo=false`、`hide_parameters=true`，应用 debug 不再开启 SQL 参数回显。

## 边界

本修复证明标准围栏不会再导致确定性失败，不代表所有真实模型输出必然符合业务 Schema。若模型返回截断、附加解释、错误字段或维度不一致，任务仍会安全失败。完整模型质量与多论文稳定性需单独验收。
