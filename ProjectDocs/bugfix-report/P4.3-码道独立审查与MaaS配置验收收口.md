# P4.3 码道独立审查与 MaaS 配置验收收口

## 审查范围

审查码道完成的 Compose MaaS 开关、LLM 配置校验、CLI 配置检查、显式付费烟测、离线测试和文档同步。码道未读取、搜索或输出用户 API Key；仅在用户明确授权后通过已配置容器执行两次最小真实请求。

## 发现的问题

1. huawei 配置检查访问 `urlparse` 不存在的 `host` 属性，真实路径直接崩溃。
2. Docker 内找不到 Compose 文件，三项测试被跳过，与项目 0 skipped 要求冲突。
3. 空白以外的说明性占位 Key 会被当作有效配置。
4. 将完整 `/chat/completions` endpoint 当作 base URL 会形成错误请求路径，却未失败前置。
5. fake transport 测试没有覆盖 CLI 自身的确认门、单次调用与空内容行为。
6. smoke 默认允许 2048 completion token，不符合最小付费烟测原则。
7. smoke 直接输出底层 LLMError，安全边界依赖下层永不回显敏感内容。
8. README 在容器重新加载 `.env` 前执行 `docker compose exec`，会检查旧配置。
9. ProjectDocs 01～08、SDD 和独立 Sprint 未记录 P4.3。
10. pytest 会继承运行容器的真实 MaaS backend 与 Key；用户切换后执行回归可能意外产生费用。

## 修正

- 使用 `parsed.hostname`，增加真实 huawei 离线子进程测试。
- 只读挂载实际 Compose 文件，移除 skip，并直接验证六项透传和 Embedding mock。
- 拒绝常见占位 Key 与完整 endpoint。
- CLI fake client 真实断言单次调用、确认前零构造、空内容失败和异常不泄密。
- smoke completion 上限固定为配置值与 32 的较小值，失败输出固定摘要。
- README 改为先重新创建 backend，再执行 config-check。
- conftest 在导入应用配置前强制两类 provider 为 mock、endpoint 为 `.invalid`，并移除继承的 LLM/Embedding API Key。
- 手工按 dev-process-framework → page-mockup（无 UI）→ fullstack-testing → function-detail → sdd-workflow → bug-fix-reporter 链路同步文档。

## 真实烟测补充修正

用户配置新 Key 并明确授权后，免费配置检查以及 DNS/TCP/TLS 均通过，首个最多 32 token 的真实请求返回安全失败。官方契约显示 GLM-5.2 默认开启深度思考，而 max_completion_tokens 同时限制思维链和回答。为避免短烟测在思考阶段耗尽额度，仅对 `maas-smoke` 显式设置 `thinking.type=disabled`；同时将底层 LLMError 映射为固定失败类别，继续禁止输出响应正文和 Key。正常审阅路径保持原行为。

修正后的 110 项定向测试和 425 项 Docker 后端全量测试均通过、0 skipped。随后按用户授权执行第二次且本轮最后一次真实请求，4.7 秒内成功并仅输出 `35 characters` 摘要；未打印模型正文、响应对象或 Key，也未进行第三次请求。该结果只证明当前账号、区域、endpoint 和模型的最小非流式连通性，不代表论文长文本审阅质量、吞吐量或生产成本已验收。
