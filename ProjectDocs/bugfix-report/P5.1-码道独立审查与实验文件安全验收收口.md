# P5.1 码道独立审查与实验文件安全验收收口

## 审查范围

审查码道实现的 008 ExperimentFile 完整性迁移、CSV/XLSX/XLS 解析器、实验文件上传/列表/详情 API、存储抽象、离线测试和文档。未读取 `.env` 或 API Key，未调用真实华为云，未修改开发库业务数据。

## 初版问题

1. 008 在增加约束前 UPDATE NULL，并 DELETE 不合格行，违反用户数据无损和只读预检要求。
2. API 对 UploadFile 一次性 `read()`，超限前已占用完整内存；扩展名/超限等早期失败不关闭文件。
3. async 路由直接执行同步解析、存储和数据库工作，阻塞事件循环。
4. 解析器以原始 bytes 为生产入口，临时文件在解析后才创建，流程顺序和安全边界错误。
5. 详情响应公开完整 SHA-256，columns_info 使用任意 dict 而非严格嵌套 schema。
6. XLSX 未完整处理反斜杠/盘符路径、重复 entry、单项压缩比、宏 ContentType、外部 relationship、OLE/ActiveX 和 `<f/>`/命名空间公式。
7. 并发重复在唯一约束竞争失败时会返回 500，且两个请求可能各自保存对象。
8. storage.save 部分失败、flush/commit 失败和 commit 后 refresh 失败的补偿存在孤儿或悬空记录风险。
9. 原始 ParseError、临时路径、用户文件名和存储 key 可能进入错误响应或不受控日志。
10. 解析/API 测试未覆盖真实 413、422、并发、失败补偿、多项 XLSX active content；全新镜像还缺少测试使用的 xlwt 依赖。
11. 规定的 Sprint 未创建，systemDesign/SDD/docs 多处仍将 P5.1 标为规划。

## 修正

- 008 只读统计不兼容行和重复键，冲突时在 DDL/DML 前中止；删除全部数据修补与清理语句。
- 以 1MiB 固定块落盘并累计实际字节，解析/存储/事务放入线程池；请求 finally 统一关闭 UploadFile 和清理临时文件。
- 解析器生产入口改为临时路径 + `ExperimentFileType`；CSV 确定性解码/分隔符和增量 dtype，XLSX 完整 ZIP/XML active content 防护，XLS OLE + xlrd。
- version=1 `columns_info` 使用 extra-forbid 嵌套 Pydantic schema；公开响应移除完整哈希和 storage_key。
- 并发唯一冲突的失败者 rollback、删除自身对象、查询胜者并返回 200；所有 storage/DB 失败补偿并使用安全日志。
- storage key 固定为不可猜 UUID 目录内 `source.csv|source.xlsx|source.xls`，PDF `source.pdf` 回归保持。
- 新增并发、413/415/422、临时/storage/flush/commit 失败、公开哈希隐藏、ZIP 穿越/重复/压缩比/宏/外链/嵌入/公式/多 sheet 和 XLS 覆盖。
- 固定 `xlwt==1.3.0`，确保干净镜像可生成 XLS 测试样本。
- 人工执行 dev-process-framework、page-mockup、fullstack-testing、function-detail、sdd-workflow 和本 bug-fix-reporter 文档链。
