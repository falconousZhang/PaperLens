## 1. 问题描述

码道实现能够通过其 57 项定向测试，但统计阶段把 CSV 原始 bytes 和 CSV/XLSX/XLS 全部数据行一次性载入内存；NaN、Infinity、非法数字和超安全整数会被静默当作 null。并发唯一约束失败返回 409 而不是幂等胜者，部分认领前异常会使任务永久停在 PENDING，完整性复核只比较列名和 dtype，事务失败分支还存在错误删除或误判已提交结果的风险。

码道只更新 Sprint、PROGRESS 和 IMPLEMENTATION_STATUS，没有按 AGENTS.md 同步 systemDesign 01～08 与 SDD。

## 2. 根本原因

- 测试只验证正常统计结果，没有验证流式边界、完整 columns_info、真实两线程竞争和数据库失败注入。
- 数值转换函数把“非法”和“空值”共用 None 表示，丢失安全错误语义。
- 后台任务在完成关系校验前设置 claimed 标记，却只允许 RUNNING 转 FAILED。
- 成功、失败和并发冲突没有统一采用“rollback 后重新查询权威状态”的策略。

## 3. 解决方案

- 在 P5.1 路径解析边界增加 CSV/XLSX/XLS 公共逐行迭代器，统计服务不再缓存原始行。
- 数值列严格拒绝非有限数、非法值、溢出和超安全整数；Welford 状态每步检查有限性，median 排序后及时释放数组。
- 完整比较 file_type、row/column 与整个 columns_info，并在统计后再次复核 SHA-256。
- 并发 loser 回查活动任务/结果并返回胜者；task/file/paper/user 四者必须同属。
- 任务认领、结果提交和失败状态提交均处理 commit 未知；失败补偿不删除任何可能已提交结果。
- 公开结果使用严格有限数 Schema，并联查 SUCCEEDED 实验任务关系。
- 同步 systemDesign、测试设计、SDD、Sprint、状态文档和 API/数据/安全文档。
