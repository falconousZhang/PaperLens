## 1. 发现的问题

1. 初版将差值实现为论文值减实验值，与契约的 `experiment_value - paper_value` 相反；论文值为零时还会产生 Infinity。
2. 重复规范化论文指标、零指标任务和损坏的 version/summary shape 没有固定失败语义。
3. Comparison Schema 与 POST 响应过于宽松，布尔、非有限数、溢出和跨字段矛盾可能进入公开 JSON。
4. 文件、结果、统计任务、指标任务、MetricRecord 与来源记录的 paper/user/task 关系没有完整复核。
5. 缺少行锁、真实并发收口、flush/commit rollback 和 commit 结果未知后的新会话回查。
6. 初版测试把错误的差值方向和零分母行为写成预期，未覆盖真实并发、事务故障、ADMIN 隔离、来源篡改与原始正文不读取。
7. 既有论文上传补偿日志会输出内部 storage key 和临时文件路径。

## 2. 修正方案

- 固定名称规范化为 NFKC→casefold→保留 `isalnum()`，只允许 MEAN→mean、MAX→max；BEST/FINAL/LAST/UNKNOWN 诚实降级为 UNVERIFIABLE。
- 固定 `diff = experiment_value - paper_value`；论文值为零时 `relative_diff = null`，其余比较按绝对/相对容差上界执行。
- 重复规范化论文指标返回 `AMBIGUOUS_PAPER_METRIC`，无指标返回 `NO_METRICS`；严格校验 version=1 统计摘要和既有 comparison。
- 使用 UUID4、枚举、有限数与跨字段 validator 固定公开 Schema；POST 只返回 file/result/task/comparisons/duplicate。
- 在锁定 ExperimentResult 后复核完整归属图；来源只查询 id/paper_id，延迟 raw_text，不读取 storage、原始行、Evidence 正文或模型输出。
- 同源并发收口为 201/200，异源竞争固定一方 409；flush/commit 失败 rollback，commit 未知以新 Session 回查已提交结果。
- 移除旧上传清理日志中的 storage key 和临时路径动态值。
