## 1. 发现的问题

1. 初版定义了 `getExperimentFile` 却未调用，页面没有展示服务端确认的 columns_info，用户无法核对可信列结构。
2. 上传只刷新列表，不选中响应文件；缺少扩展名、非空和 20MB 客户端快速校验，并手写 multipart Content-Type，存在 boundary 错误风险。
3. 文件列表固定请求第一页，没有分页；成功指标任务按 API 原顺序默认，不保证选择最新历史任务。
4. GET result 已包含 metric_comparisons 时仍忽略结果并要求用户再次 POST，可能产生不必要冲突；已有来源也没有锁定。
5. 轮询只绑定页面代数，切换实验文件后仍在途的旧任务响应可能修改新文件状态；comparison 响应也未复核来源任务与行级 task id。
6. 网络异常、任务 error_message 和服务端 message 会直接展示，可能泄漏内部实现信息；初版测试反而断言必须出现这些原始错误。
7. 码道新增 `design/09-experiment-frontend.md`，与既有 `09-API接口详细设计.md` 编号冲突，且多个状态文档仍写 P5.3b 未开始。

## 2. 修正方案

- 选择文件后并行加载可信详情与已有结果，校验 file/paper 上下文；详情失败支持独立重试。
- 上传前拒绝不支持扩展名、空文件和超过 20MB 的文件；由浏览器生成 multipart boundary；上传成功后刷新第一页并选中响应 id。
- 实验文件按 20 条分页，翻页清空旧选择；成功指标任务按 created_at/id 稳定降序，默认最新。
- 将已有 metric_comparisons 转为只读 comparisonResult，校验全部行使用同一 metric_task_id 并锁定来源；无指标任务时提供指标页入口。
- 页面 generation、文件 selection generation 和 paper/file/task id 共同约束所有异步回调；切换文件、路由或卸载后丢弃陈旧轮询和比较响应。
- 未知网络/API/任务错误全部映射为固定公开文案；分析失败只允许固定安全错误集合；数值 null 统一显示 em dash。
- 修订测试契约，新增可信详情、上下文错配、分页、本地上传边界、上传后选中、最新任务、已有结果恢复、旧轮询隔离和错误脱敏覆盖。
- 将重复设计内容并入既有 05/07/10 设计文档并删除冲突文件，同步 systemDesign 01～08、SDD、Sprint 和状态文档。
