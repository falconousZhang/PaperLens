## 发现的问题

1. 活跃唯一索引只含用户、论文和选项，READY 后永久阻止同一论文的新来源报告。
2. source_snapshot 在 POST 创建，但后台重新选择最新任务，快照与实际文件可能不一致。
3. 报告尾部使用当前时钟；所谓确定性测试在同一秒调用两次，无法证明跨时间逐字节一致。
4. Finding 只输出 Evidence id，并错误标为“证据页”，缺少真实页码和短引用。
5. 普通文本只做 HTML escape，换行后的标题、列表和 Markdown link 可破坏结构。
6. Review/Metric/Experiment 来源图未逐层复核，跨论文关联可能被静默汇总。
7. 并发创建没有 IntegrityError 回查，后台没有条件认领；存储成功但数据库失败可能遗留未归属对象。
8. 010 将所有历史报告硬限制为 MARKDOWN，并通过把认证测试 PDF 改成 MARKDOWN 隐藏兼容问题。
9. 原测试没有真实创建并发、新来源、关系篡改、部分 storage 写入、FAILED 重试或历史行迁移覆盖；终态断言存在条件空跑。

## 修复结果

- 新增 011 迁移与 source_hash；幂等键包含来源和内容哈希，FAILED 不阻止重试，历史 PDF/DOCX 行兼容。
- 创建时完成来源图复核与确定性渲染，后台只接收固定 bytes；条件 UPDATE 保证单 worker 认领。
- storage 保存后回读比对，READY 原子提交；提交未知回查，未归属对象重试删除并固定 FAILED。
- 生成时间改取来源任务时间；Evidence 输出页码与短引用；补齐 Markdown/HTML/表格/URL scheme 转义。
- 请求与响应使用严格 Schema；内部快照、哈希和对象 key 不进入 API；下载复核完整性并增加 no-store。
- 恢复认证测试中的历史 PDF 语义，新增迁移历史行和无损拒绝测试。
