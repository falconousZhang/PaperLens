## 问题与根因

| 问题 | 根因 | 风险 |
|------|------|------|
| PDF 中文提取为 `I` | 默认 Helvetica 不包含中文，测试只断言非空 | 中文报告不可检索、复制内容错误 |
| PDF 生成后替换 metadata bytes | 未使用 ReportLab 原生 invariant/metadata 能力 | 对象偏移失真，依赖阅读器容错 |
| DOCX 外部关系测试无效 | 只检查 ZIP entry 文件名是否含 external | External relationship 可漏检 |
| DOCX rsid 未清理 | 仅固定 ZIP timestamp/core | 确定性契约不完整 |
| 历史页面无真实分页 | listExports 永远使用默认第一页 | 超过 20 条后无法访问历史 |
| 异步响应可覆盖当前页 | 没有 route/page request generation | 翻页或切换论文后显示陈旧数据 |
| 历史/下载失败静默 | catch 为空 | 用户无法重试或判断失败 |
| 下载测试空洞 | 未验证 create/revokeObjectURL | blob URL 泄漏回归不可见 |
| FAILED 详情直接进入严格 Schema | 复用数据库 error_message | 历史异常值可能 500 或泄漏内部信息 |

## 修正内容

1. PDF 使用 ReportLab invariant 和 STSong-Light，固定元数据并直接生成合法确定性文件；PyMuPDF 逐字验证中英文。
2. DOCX 重打包固定 entry 顺序、timestamp、权限，清除 rsid；逐个解析 relationship，并拒绝宏、OLE、嵌入对象和 External。
3. 012 downgrade 对全部 PDF/DOCX 行无损中止；测试覆盖 PostgreSQL 事务性多 revision rollback。
4. ReportExportView 增加 20 条分页、总页数、请求代数、路由变化处理、轮询清理、历史重试、下载锁和安全错误。
5. blob URL 和临时 anchor 在 finally 中清理；API FAILED 响应统一固定公开文案。
