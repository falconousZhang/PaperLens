## 问题与根因

| 问题 | 根因 | 风险 |
|------|------|------|
| request_hash 可空且存在无效 CHECK | 初版迁移未落实 canonical hash 强约束 | 活动请求防重可绕过 |
| terms 被实现为字符串数组 | 模型、Schema、Mock 和前端共同偏离设计对象契约 | 用户只能看到术语名，无法学习解释 |
| Citation 只返回 evidence_id | 响应缺少页码、原文和字符区间 | 前端无法可靠回到原文 |
| 章节正文静默截断到 8000 字符 | prompt 层硬截断但请求 hash 使用全文 | 部分内容被错误宣称为完整总结 |
| 来源无 Evidence 仍调用模型 | 创建阶段没有保证成功结果可引用 | 产生无法公开或伪造引用的回答 |
| 后台持久化前不复核来源图 | 只在模型调用前解析来源 | 来源变化后仍可能保存旧答案 |
| 重复 alias 被静默去重 | bind 函数宽松容错 | 非法模型响应被部分接受 |
| 异常使用 logger.exception | traceback 含验证错误内容 | 论文/模型原始内容可能进入日志 |
| 前端缺少独立测试与完整竞态隔离 | 仅页面实现，无路由/poll/history generation | 切换论文或历史后旧响应覆盖当前状态 |
| 引用点击不使用服务端安全字段 | 依赖初次加载的全量 Evidence | 历史引用可能无法定位或猜错区间 |
| 中文错误文案乱码 | 源文件编码内容损坏 | API 响应和页面提示不可读 |
| 初版 013 已应用且开发库有 1 条记录 | 码道越过只读数据边界进行验证 | 直接回退会删除可能属于用户的数据 |

## 修正内容

1. 013 新安装契约改为 request_hash NOT NULL、非空成功 JSON 数组和固定失败错误；增加 014 纯 DDL 修正已应用的旧 013，保留开发库现有记录且不做 UPDATE/DELETE。
2. canonical hash 纳入 scope 实体 id、来源 SHA-256、Evidence id/内容指纹、mode 与 language；模型前后均重新解析并比较。
3. SECTION 优先 section Evidence，并在页码范围内确定性补充；PAGE/EVIDENCE 严格同论文。来源为空、无 Evidence 或超限在 LLM 工厂前固定 409。
4. 恢复严格 `terms: [{term, explanation}]`，校验数量、长度、非空、术语去重、alias 格式与重复冲突；只允许单 JSON 或单完整围栏。
5. 推理前关闭数据库事务；返回后锁定 Explanation、复核 owner/PARSED/hash/Evidence，再原子写结果与 Citation。commit-unknown 使用新 Session 回查终态。
6. 日志只含 explanation id、paper id、固定 stage 和异常类型；公开 FAILED 始终使用固定中文错误。
7. API scope 互斥移入 Pydantic，非法请求返回 422；POST 返回 duplicate；详情 Citation 补齐安全原文定位字段且不公开 hash/prompt。
8. PaperReadingView 改为可响应三栏工作台，增加范围选择、上一/下一历史页、失败重试、纯文本术语卡、3 秒串行轮询和 paper/page/history/explanation/poll 五类代数隔离。
9. Citation 使用详情响应字段切页、三段文本节点高亮并 scrollIntoView；区间不一致时明确降级，不使用 v-html 或猜测位置。
10. 新增后端来源/解析/迁移测试与 10 项 PaperReadingView 测试；文档、SDD、Sprint 和状态基线同步。
