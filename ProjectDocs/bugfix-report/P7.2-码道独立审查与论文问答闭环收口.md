# P7.2 码道独立审查与论文问答闭环收口

## 1. 问题描述

码道初版能够跑通其自带的 33 项后端和 10 项前端测试，但与 P7.2 契约存在系统性差距：015 缺少 Turn 的 user_id/paper_id、活动部分唯一索引、问题/成功/失败严格 CHECK 与非空降级保护；API 没有双分页和会话摘要；检索逐条调用 Embedding 并吞掉非法向量；历史无字符预算；context_hash 缺少身份、问题/回答和 Evidence 文本指纹；模型返回后未复核来源图；前端缺失败重试、真实分页和完整异步隔离。设计、SDD 与 Sprint 也未同步。

## 2. 根本原因

实现只覆盖了最短成功路径，测试主要验证端点可调用和基本显示，没有逐条落实提示词中的数据库不变量、生成前后来源一致性、严格向量错误、分页响应和竞态场景。容器又未挂载源码，首次看到的旧测试通过实际运行的是码道镜像内旧代码，不能证明修正生效。

## 3. 解决方案

- 重写 015 与 ORM：三实体完整外键、状态 CHECK、幂等/sequence/活动唯一、空表往返和非空无损拒绝。
- 重写 qa schema/service/retriever/API：严格输入与安全响应、owner-only 双分页、批量向量校验、完整历史预算、canonical context_hash、生成后全图复核、原子成功与安全失败补偿。
- 收口 PaperReadingView：空会话、会话/轮次分页、3 秒串行轮询、失败新 UUID 重试、证据不足样式、Citation 原文定位和 paper/conversation/turn/action/poll 代数隔离。
- 扩充迁移、API、服务、非法向量、来源变化和 Vue 测试；同步 systemDesign 01～08、SDD、Sprint、README 与 docs。
- 修正三条旧迁移测试对 head=014 的硬编码；P7.2 后失败降级的事务回滚应保持 head=015。
