## 问题现象

P8.3 初版的 `request_tracing.py` 在模块导入时构造空 UUID，应用无法启动。UUID 校验会把任意可解析 UUID 强制改写为 v4 后判定通过，却把原始非规范值写回响应。未知路由日志回退到原始 URL，可能记录资源 ID。限流桶把 `expires_at` 与 `now-window` 比较，使 60 秒窗口约 120 秒才重置；实验上传真实路由未归入 upload。测试又对文档规定豁免的 health 端点期待 429，因此无法验证真实契约。

同时，可信代理解析会跳过非法地址并选择错误 hop，配置只在首请求惰性失败；异常处理记录 traceback，可能带出异常正文；async readiness 直接执行同步数据库访问；recovery submitter 把参数 tuple 当成一个参数传入，executor shutdown 不等待任务。ReviewResult 两条冲突的 selectinload 可能重新加载未验证 Finding；Evidence 固定 `.limit(500)` 会静默丢失长论文证据。P8.3 只更新了部分设计文档，并把归档第 31 节误写为“第 32 节”。

## 根因

1. 请求追踪、限流和测试资产由接口形状推演，未执行最小导入和契约核对。
2. 固定窗口把“到期时间”和“历史 cutoff”两种语义混用。
3. 路径分类使用不存在的静态实验上传前缀，没有对照真实 FastAPI 路由。
4. 代理链、异常日志和 executor 只覆盖顺利路径，没有校验关闭、非法输入和路由前返回。
5. 查询优化以固定截断替代分页/契约分析，忽略 PaperLens 以完整论文证据为核心的产品目标。

## 修复方案

- 删除非法 UUID 初始化，严格要求规范小写 UUID4；成功、404、429 和安全 500 均回传 request id。
- 未匹配或路由前返回统一日志为 `<unmatched>`；日志不记录原始路径、query、IP、header、正文或异常正文。
- RateLimiter 使用可注入单调时钟，按 `expires_at <= now` 准时重置，Retry-After 向上取整；store 过期清理并限制最大 key 数。
- 对照真实路由集中分类认证、论文上传和动态实验上传；health 精确豁免。
- 配置改为 `PAPERLENS_TRUSTED_PROXY_CIDRS` 并在 Settings 初始化时验证；只有直接 peer 可信才从右向左剥离可信代理，任一非法地址回退直接 peer。
- readiness 改为同步端点，由 FastAPI 线程池执行；数据库失败只返回固定 503。
- executor 增加线程安全创建、参数展开注入、shutdown 取消排队任务并等待已运行任务；保持 P8.2 状态机不变。
- ReviewResult 使用单条带 VERIFIED 条件的 selectinload；问答空页不再执行两条无效批量查询；撤销 Evidence 固定 500 截断。
- 重写恰好 3 个 P8.3 测试，覆盖严格追踪/日志脱敏、真实窗口/有限 store/health 豁免、ready 成功与安全失败；同步 systemDesign 01～08、SDD、Sprint 和根文档。
