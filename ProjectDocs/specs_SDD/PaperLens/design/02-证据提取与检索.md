# 证据提取与检索模块设计

## 文档信息

| 项目 | 内容 |
|------|------|
| 模块编号 | 02 |
| 模块名称 | 证据提取与检索 |
| 实现状态 | Evidence 提取与 P3.2 任务内语义检索已实现；持久化向量索引未实现 |
| 关联需求 | FR-02.1.x, FR-02.2.x |

## 1. 模块概述

证据提取与检索模块负责从论文中提取原文 Evidence（page-local 定位），并为审阅维度检索相关 Evidence。P3.2 当前对同论文 Evidence 做任务内即时 Embedding 和精确余弦 Top-K；持久化 FAISS/pgvector 索引仍是后续规划。Evidence 是 PaperLens 的核心概念，每条公开审阅结论必须绑定至少一个 Evidence，确保可追溯性。

## 2. 后端设计

### 2.1 Evidence 提取服务（已实现）

**核心流程:**

1. 基于 PyMuPDF block 提取页内文本块
2. 生成 quoted_text（证据原文引用文本）
3. 计算真实 bbox 坐标（bbox_x0/y0/x1/y1）
4. 计算 char_start / char_end（在 normalized_text_content 中的字符偏移）
5. 关联 chunk_id 和 section_id
6. 标注 evidence_type（TEXT / TABLE / FIGURE_CAPTION / EQUATION）

**关键实现:**

- page-local 定位: Evidence 不涉及跨页 span，基于 PyMuPDF block 天然页内
- 真实 bbox 坐标: 直接使用 PyMuPDF 提取的 block bbox
- char 偏移计算: 在 normalized_text_content 中查找 quoted_text 的字符区间
- 降级处理: char 区间不匹配时设为 null，前端显示降级提示

**API 接口:**

| 接口 | 方法 | 路径 | 状态 | 说明 |
|------|------|------|------|------|
| 获取证据列表 | GET | /api/v1/papers/{paper_id}/evidences | ✅ CURRENT | 不支持 page_number / evidence_type 过滤（📋 PLANNED） |
| 获取证据详情 | GET | /api/v1/evidences/{evidence_id} | ✅ CURRENT | 含页面内定位信息 |

**数据模型:**

| 表名 | 说明 |
|------|------|
| evidences | 证据表（quoted_text, page_number, bbox, char_start, char_end, evidence_type, chunk_id, section_id） |

### 2.2 向量索引服务（未实现）

**核心流程:**

1. 调用 Embedding 模型向量化 PaperChunk
2. 使用 FAISS 建立向量索引（IndexFlatIP）
3. 索引序列化到 OBS 持久化
4. 回填 PaperChunk.embedding_id

**关键设计:**

- Embedding 模型: 通过独立 EmbeddingClient 接口调用
- FAISS 索引: IndexFlatIP（内积），后续可迁移至 Milvus
- 索引持久化: 序列化到 OBS，加载后缓存在内存

**待实现 API:**

| 接口 | 方法 | 路径 | 状态 | 说明 |
|------|------|------|------|------|
| 构建向量索引 | POST | /api/v1/papers/{paper_id}/index | 📋 PLANNED | 触发向量索引构建任务 |
| 证据列表过滤 | - | /api/v1/papers/{paper_id}/evidences | 📋 PLANNED | page_number / evidence_type 查询参数 |

### 2.3 语义 Evidence 检索服务（P3.2 已实现）

**核心流程:**

1. 仅加载目标 paper 的 `id/quoted_text/page_number/created_at`，按页码、创建时间和 ID 稳定排序
2. 结束数据库只读事务，再调用 EmbeddingClient；外部推理期间不持有 SQLAlchemy 事务
3. Evidence 文本在一次任务中只向量化一次，并按请求维度构造中英文 query
4. 对每个维度计算精确 cosine similarity，按分数降序、页码/创建时间/ID 升序稳定打破平分
5. 每个维度返回 `review_evidence_top_k` 条 Evidence，并重新建立 E1/E2… 临时 alias

**关键设计:**

- Top-K 检索: 默认 K=8
- Embedding 实现: 默认离线 MockEmbeddingClient；可配置 HuaweiMaaSEmbeddingClient
- 输入输出验证: 数量、顺序、维度、有限数值、非零范数均严格检查
- 华为适配: HTTPS、Bearer、batch、`data[].index` 恢复、连接复用和安全错误；API Key 仅来自环境配置
- 失败语义: 任一 Evidence/查询/batch 失败则整个 REVIEW 任务 FAILED，不写入部分 ReviewResult/Finding/关联
- 当前边界: 不建立 FAISS/pgvector，不持久化向量，不回填 `PaperChunk.embedding_id`

## 3. 前端设计

### 3.1 证据列表展示（已实现）

**核心功能:**

- 证据 Tab 展示证据列表
- 每条显示页码、类型、引用文本
- 点击证据项跳转到页面 Tab 高亮

### 3.2 Evidence 高亮（已实现）

**高亮机制:**

1. 前端获取 Evidence 的 char_start / char_end
2. 在 normalized_text_content 中标记字符区间
3. 高亮背景色: #fff176（黄色）
4. 高亮后 scrollIntoView 定位

**降级处理:**

- char 区间为 null: 显示降级提示，不高亮
- char 区间越界: 显示降级提示，不高亮
- 高亮文本与 quoted_text 不匹配: 显示降级提示，不高亮

## 4. 关键设计决策

| 决策 | 说明 |
|------|------|
| page-local Evidence | PyMuPDF block 天然页内，bbox 坐标准确，跨页场景极少 |
| char 偏移降级 | char 区间不匹配时设为 null，前端优雅降级 |
| 即时精确余弦检索 | 先完成单论文可验证召回，不引入持久化索引基础设施 |
| Embedding 接口可替换 | 默认 Mock 保证离线测试；生产方向优先华为云 MaaS |
| FAISS/pgvector（规划） | 仅在需要跨任务缓存或更大规模检索时引入，后续可迁移 Milvus |
