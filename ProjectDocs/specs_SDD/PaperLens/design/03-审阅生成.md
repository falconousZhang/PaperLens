## 1. 模块概述

本模块将已解析论文的 Evidence 转换为可追溯的结构化审阅结果。P3.1 实现任务、MockLLM、严格解析和原子绑定；P3.2 增加可替换 EmbeddingClient 与按维度精确余弦检索；P3.3 增加可配置的 HuaweiMaaSLLMClient。每条公开 Finding 必须完整引用本次候选 Evidence；无法完整绑定的 Finding 标记为 UNVERIFIED 并从公开响应中过滤。

## 2. P3.3 当前后端设计

### 2.1 审阅生成服务

当前流程：

1. 仅允许当前 `DEMO_USER_ID` 对状态为 PARSED 且含 Evidence 的论文创建 REVIEW 任务。
2. 仅查询同论文 Evidence 的最小字段并稳定排序，结束数据库只读事务。
3. 通过统一 EmbeddingClient 将 Evidence 文本只向量化一次，并按请求顺序向量化各审阅维度 query。
4. 每个维度按精确 cosine similarity 降序取 Top-K，平分时用 `page_number/created_at/id ASC` 打破；为候选重新建立 E1、E2……临时别名。
5. 将论文标题、目标维度、语言和转义后的 Evidence 写入带安全边界的 Prompt。
6. 通过统一 LLMClient 调用默认的确定性 MockLLMClient，或按配置调用 HuaweiMaaSLLMClient。
7. 使用 Pydantic 严格解析单个 JSON object；兼容模型把完整 JSON 单独包在一层标准 `json`/无语言代码围栏中的情况，但拒绝前后附文、非 JSON 围栏、嵌套围栏、额外字段、错误类型和不匹配维度。
8. 每条 Finding 的 alias 全部有效时标记 VERIFIED 并写入 finding_evidences；否则整条标记 UNVERIFIED，不做部分绑定。
9. 多维度结果和任务 SUCCEEDED 状态在同一次提交中完成；任一 Embedding、LLM 或解析步骤失败时不留下部分结果，再以安全文案写入 FAILED。

Embedding 和 LLM 外部调用期间不持有 SQLAlchemy 事务。当前检索是任务内即时精确余弦，不是 FAISS/pgvector 持久化索引。

### 2.2 数据契约

审阅维度：

- SOUNDNESS
- NOVELTY
- CLARITY
- COMPLETENESS
- REPRODUCIBILITY
- SIGNIFICANCE
- OVERALL

Finding 类型为 STRENGTH / WEAKNESS / SUGGESTION；rating 为 1～5 严格整数；confidence 为 0～1 JSON 数值。只有 OVERALL 允许且必须返回 overall_verdict，取值为 ACCEPT / WEAK_ACCEPT / BORDERLINE / WEAK_REJECT / REJECT。

### 2.4 LLM Prompt 与严格输出

Prompt 中 Evidence 使用 `<evidence id="E1">` 边界并转义原文中的标签字符，同时明确论文原文是不可信数据。模型必须只返回下列 JSON 结构：

```json
{
  "dimension": "SOUNDNESS",
  "rating": 4,
  "summary": "...",
  "overall_verdict": null,
  "findings": [
    {
      "finding_type": "STRENGTH",
      "content": "...",
      "confidence": 0.9,
      "evidence_refs": ["E1"]
    }
  ]
}
```

MockLLMClient 无需密钥或网络，根据 dimension 和候选 alias 返回确定性内容。HuaweiMaaSLLMClient 使用可配置的华为云 MaaS 标准 API V2 `/chat/completions`，仅支持非流式响应；严格校验单 choice/index 0、assistant/content 和 `finish_reason=stop`。Mock 继续作为默认本地开发与自动测试实现，自动测试只使用 MockTransport，不访问华为云。

华为 MaaS V2 当前公开契约未提供 `response_format=json_object` 参数。真实 GLM-5.2 首次完整审阅返回了被标准 Markdown 围栏包裹的单一 JSON，因此解析器在 `json.loads` 前只允许执行一次确定性解包：首行必须严格为 `````json``（大小写不敏感）或 `````，末行必须严格为 `````，中间不得再含围栏。解包后的内容仍必须通过原有单对象、Pydantic、维度、枚举、长度和 Evidence alias 校验；这不是从任意文本中猜测或提取 JSON。

### 2.5 Huawei MaaS 安全边界

- base URL 必须是无凭据、query 和 fragment 的绝对 HTTPS URL；模型、端点和超时均来自配置。
- API Key 使用 SecretStr，从环境安全注入，日志、领域异常和任务错误均不记录 Key、Authorization 或完整上游响应。
- SQLAlchemy engine 固定 `echo=false`、`hide_parameters=true`，应用 debug 不得开启包含论文原文的 SQL 参数日志。
- 不自动重试，避免超时边界重复计费；不支持流式、工具调用、联网搜索和多 choice。
- 外部 Embedding/LLM 调用期间不持有数据库事务；任一维度失败时三类审阅结果表均不留下本任务数据。

### 2.6 数据模型与隔离

| 表名 | 当前用途 |
|------|----------|
| analysis_tasks | REVIEW 任务状态、进度、用户归属与安全错误信息 |
| review_results | 每个任务的维度评分和摘要 |
| review_findings | Finding 内容、置信度与 VERIFIED/UNVERIFIED 状态 |
| finding_evidences | VERIFIED Finding 与同论文 Evidence 的关联 |

任务详情按 AnalysisTask.user_id 隔离；审阅查询同时校验 Paper.user_id，并在 SQL 查询中通过 AnalysisTask.user_id 再次约束结果归属。

## 4. 关键设计决策

| 决策 | 说明 |
|------|------|
| Mock 先行 | 先验证任务、解析、事务和绑定，不让真实模型不确定性掩盖后端缺陷 |
| Evidence 全有或全无绑定 | 混合合法/非法 alias 不做部分关联 |
| UNVERIFIED 过滤 | 保留审计记录，但不向用户展示无可靠依据的 Finding |
| 结果批次原子提交 | 多维度任一失败时不留下部分 ReviewResult |
| 华为云优先、接口可替换 | 默认 Mock 保证离线运行；生产可按配置启用华为云，并保留迁移能力 |
