# 指标提取与口径判断模块设计

> **状态：P4.1 后端与 P4.2 指标前端已完成独立验收收口。**

## 文档信息

| 项目 | 内容 |
|------|------|
| 模块编号 | 04 |
| 模块名称 | 指标提取与口径判断 |
| 当前范围 | 确定性后端提取、异步任务、查询 API、真实用户隔离与指标前端交互 |
| 非本轮范围 | CSV/Excel、报告、真实华为云推理 |
| 关联需求 | FR-04.1.x、FR-04.2.x |

## 1. 设计目标

从当前用户已解析论文的 `PaperTable.structured_data/raw_text` 和 Evidence 中提取可追溯指标。系统不得补算、猜测或生成论文没有提供的数值；所有公开 `MetricRecord` 必须且只能绑定一种来源：`table_id + row_index` 或 `evidence_id`。

## 2. 执行流程

1. `POST /api/v1/papers/{paper_id}/tasks` 校验 Bearer 会话、论文所有权和 `PARSED` 状态。
2. 在创建任务前执行确定性候选预检；没有可用候选返回 `409 NO_CANDIDATES`，不创建空任务。
3. 同一用户、论文只能存在一个 `PENDING/RUNNING` 的 `METRIC_EXTRACTION` 任务；应用检查和数据库部分唯一索引共同防并发重复。
4. 后台任务先把表格和 Evidence 读取为不可变来源快照，然后结束读事务，再执行纯 Python 解析。
5. 写入前重新校验 task、paper、user 和每个来源绑定；全部 MetricRecord 与 `SUCCEEDED` 状态在一个事务提交。
6. 任一候选或数据库写入失败时回滚本 task 的全部 MetricRecord，并把任务安全标记为 `FAILED`。

## 3. 确定性提取口径

### 3.1 指标名

支持并规范化 `accuracy/acc`、`precision`、`recall`、`F1/F1-score`、`AUC/AUROC`、`mAP/AP`、`BLEU`、`ROUGE`、`IoU/mIoU`、`RMSE`、`MAE`、`loss`。表格中的未知指标列可保留原始名称，但年份、epoch、batch、样本量、参数量、学习率等非指标列必须拒绝；Evidence 正文只提取明确支持的指标别名。

### 3.2 数值

- 支持整数、小数、前导小数、科学计数法和百分号。
- 带 `%` 的值统一除以 100，API 与数据库都使用 0～1 口径；百分比指标的无 `%` 值只有位于 0～1 时才接受。
- 非百分比指标允许有限负数；负百分比拒绝。
- `NaN`、`Infinity`、空值、范围、均值 `±` 标准差、年份和样本量拒绝。

### 3.3 模型和数据集

只有表头明确标记 `model/method/architecture/system` 或 `dataset/data/corpus/benchmark` 时，才从同一行相应单元格提取 `model_name` 或 `dataset_name`。不能把指标表头、章节名、caption 或任意行首文本同时当成模型和数据集；证据不足时为 `null`。

### 3.4 Checkpoint

只检查当前表格 caption、当前行标签或当前 Evidence 文本中的完整关键词：`FINAL/MAX/MEAN/BEST/LAST`。同一候选出现冲突或没有明确证据时均存 `UNKNOWN`；系统绝不根据数值最大自动推断 `BEST/MAX`。`checkpoint_source` 只记录实际命中的 `caption`、`row_header`、`context` 或冲突标记 `conflict`。

### 3.5 去重与排序

同一 task 内按规范指标名、数值、模型、数据集、Checkpoint 去重；表格行来源优先于 Evidence。候选和查询结果都使用显式稳定排序，并以 id 作为最终 tie-breaker。

## 4. 数据约束

`MetricRecord` 包含 `paper_id/task_id/user_id`、模型、数据集、指标名和值、Checkpoint、来源及最小必要 `raw_text`。数据库约束要求：

- `metric_value` 必须有限；
- `checkpoint_type` 非空且属于六种枚举；
- 表格来源必须同时有非负 `row_index` 且没有 `evidence_id`；
- Evidence 来源必须没有 `table_id/row_index`；
- 来源外键删除策略为 `RESTRICT`，避免保留失去证据的公开记录；
- 用户删除仍不得级联清空业务数据。

## 5. API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/papers/{paper_id}/tasks` | `task_type=METRIC_EXTRACTION`，options 只能为空对象或省略 |
| GET | `/api/v1/papers/{paper_id}/metrics` | task_id、metric_name、dataset_name、checkpoint_type、分页过滤 |
| GET | `/api/v1/metrics/{metric_id}` | 单条详情；越权按不存在处理 |

普通 USER 和 ADMIN 均不能越过资源所有权。`user_id` 只取认证依赖，body/query/header 伪造无效。

## 6. 测试基线

测试覆盖别名、Unicode/未知表头、全部数值边界、Checkpoint 冲突和 UNKNOWN、模型/数据集降级、来源校验、稳定去重、空候选、并发活动任务、后台成功/失败原子性、过滤分页、严格 schema、未认证与 USER/ADMIN 隔离。数据库集成测试只使用 `paperlens_test`，结束后所有业务表必须为空。

## 7. 前端边界

P06 `MetricAnalysisView` 已在 P4.2 实现。页面只列出成功指标任务并始终以 `task_id` 隔离结果；活动任务运行期间保留上一轮成功结果；筛选与分页由后端完成。Evidence 来源跳转论文详情 query，表格来源仅显示 ID、0-based 行号与原文，不生成不存在的表格详情路由。双来源或无来源结构统一降级为“来源不可用”。
