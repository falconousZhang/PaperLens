## 1. 模块概述

指标提取与口径判断模块负责从论文表格和正文中提取实验指标（模型名、数据集、指标名、指标值），并识别统计口径（final/max/mean/best/last），标注口径来源。

## 2. 后端设计

### 2.1 指标提取服务

**核心流程:**

1. 从 PaperTable 的 structured_data 中提取指标
2. 识别模型名、数据集名、指标名、指标值
3. 关联来源 Evidence 和表格行号
4. 写入 MetricRecord

**关键设计:**

- 表格解析: 从 structured_data（JSONB）中按行列提取
- 指标识别: 基于规则引擎 + LLM 辅助识别
- Evidence 关联: 每条 MetricRecord 关联来源 Evidence
- 表格行号: 记录 row_index 用于追溯

**API 接口:**

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 创建指标提取任务 | POST | /api/v1/papers/{paper_id}/tasks | task_type=METRIC_EXTRACTION |
| 获取指标记录 | GET | /api/v1/papers/{paper_id}/metrics | 支持 model_name / dataset_name / checkpoint_type 过滤 |

**数据模型:**

| 表名 | 说明 |
|------|------|
| metric_records | 指标记录表（model_name, dataset_name, metric_name, metric_value, checkpoint_type, checkpoint_source, evidence_id, table_id, row_index） |

### 2.2 Checkpoint 口径判断服务

**核心流程:**

1. 基于规则引擎判断 checkpoint_type
   - 关键词匹配: "final" → FINAL, "best" → BEST, "max" → MAX, "mean" → MEAN, "last" → LAST
   - 上下文分析: 表头、脚注、正文描述
2. 标注口径来源
   - EXPLICIT_TEXT: 显式文本标注（如 "best result"）
   - TABLE_HEADER: 表格标题推断（如表头含 "Best"）
   - IMPLICIT_CONTEXT: 隐式上下文推断
   - UNKNOWN: 无法判断
3. LLM 辅助歧义消解（仅消解歧义，不参与数值计算）

**关键约束:**

- LLM 不参与任何数值计算
- 规则引擎优先，LLM 仅辅助歧义消解
- UNKNOWN 为兜底选项

**checkpoint_type 枚举:**

| 类型 | 说明 |
|------|------|
| FINAL | 最终值 |
| MAX | 最大值 |
| MEAN | 均值 |
| BEST | 最佳值 |
| LAST | 最后值 |
| UNKNOWN | 未知 |

## 3. 前端设计

### 3.1 指标分析页面 (P06 MetricAnalysisView)

**核心功能:**

- 筛选栏：模型名、数据集、Checkpoint 口径下拉筛选
- 指标表格：模型名、数据集、指标名、指标值、口径类型、口径来源
- 口径标签：FINAL/MAX/MEAN/BEST/LAST 以不同颜色标签展示
- 行展开：点击表格行展开详情（来源证据、表格行号、证据链接）
- 空状态：未提取指标时显示"提取指标"按钮

**交互行为:**

| 交互 | 行为 |
|------|------|
| 页面加载 | 调用 GET /papers/:id/metrics |
| 筛选变更 | 根据筛选条件重新请求或前端过滤 |
| 点击表格行 | 展开该行详情面板 |
| 点击"查看证据" | 切换到页面 Tab，跳转并高亮 Evidence |
| 无指标数据 | 显示"提取指标"按钮，调用 POST /papers/:id/tasks |

## 4. 关键设计决策

| 决策 | 说明 |
|------|------|
| 规则引擎优先 | 确定性判断，避免 LLM 幻觉 |
| LLM 仅辅助歧义消解 | 不参与数值计算，保证结果确定性 |
| UNKNOWN 兜底 | 无法判断时不强行标注，保持诚实 |
