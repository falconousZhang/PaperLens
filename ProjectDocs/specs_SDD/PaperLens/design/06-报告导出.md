## 1. 模块概述

报告导出模块负责将审阅结果、指标记录和实验分析结果导出为多种格式（Markdown / PDF / DOCX），支持中英文语言选择。

## 2. 后端设计

### 2.1 报告生成服务

**核心流程:**

1. 接收导出请求（report_type, language, include_metrics, include_experiment_analysis）
2. 校验完整来源图并生成只含 id 的 source_snapshot
3. 在写 PENDING 前生成确定性 Markdown bytes、content_hash 和 source_hash
   - Markdown: 直接拼接 Markdown 文本
   - PDF: 基于 Markdown 转换
   - DOCX: 基于 Markdown 转换
4. 存储导出文件（StorageBackend）
5. 更新 ExportReport 记录（状态: READY）

**关键设计:**

- 报告格式: MARKDOWN / PDF / DOCX
- 报告语言: zh / en
- 包含选项: include_metrics（是否包含指标记录）、include_experiment_analysis（是否包含实验分析）
- 进度轮询: HTTP 轮询导出进度

**P6.1 已实现细节:**

- 状态机: PENDING → GENERATING → READY / FAILED；FAILED 允许重试
- 幂等创建: 部分唯一索引包含 user/paper/type/language/include 选项/source_hash/content_hash；同源新建 201、重复 200，不同来源可并存，FAILED 可重试
- 确定性输出: 创建时固定来源 bytes，生成信息取来源任务时间；后台只存这些 bytes，不重新选择最新任务
- 安全: HTML/Markdown 转义；禁止输出 storage_key、content_hash、raw_text、内部路径、tokens 等字段
- 下载安全: Content-Type: text/markdown; charset=utf-8，Content-Disposition: attachment，nosniff，private/no-store，发送前复核 size/hash
- 新增文件: schemas/export.py、services/export_service.py、api/exports.py

**API 接口:**

| 接口 | 方法 | 路径 | 状态 | 说明 |
|------|------|------|------|------|
| 生成导出报告 | POST | /api/v1/papers/{paper_id}/exports | ✅ P6.2 | 创建导出任务，支持 MARKDOWN/PDF/DOCX，201/200 幂等 |
| 获取导出状态 | GET | /api/v1/exports/{export_id} | ✅ P6.1 | 轮询导出进度 |
| 导出历史列表 | GET | /api/v1/papers/{paper_id}/exports | ✅ P6.2 | 分页列表，仅论文所有者可见 |
| 下载报告 | GET | /api/v1/exports/{export_id}/download | ✅ P6.2 | 三格式 MIME 文件流下载 |

**数据模型:**

| 表名 | 说明 |
|------|------|
| export_reports | 010 新增 language/include/source_snapshot；011 新增 source_hash、来源感知唯一索引与严格终态/哈希约束；012 调整 ck_export_p61_source 支持三格式 |

### 2.2 Markdown 报告模板

**P6.1 已实现模板结构:**

- zh/en 双语模板，按维度排序审阅详情
- 可选指标表格（include_metrics）：模型、数据集、指标、值、口径
- 可选实验分析（include_experiment_analysis）：统计摘要 + 交叉验证比较（MATCH/MISMATCH/UNVERIFIABLE）
- HTML/Markdown 转义；Finding 的 Evidence 输出真实页码与规范化短引用；禁止字段过滤

**报告结构（规划参考）:**

```markdown
# {paper_title} - 审阅报告

## 论文信息
- 标题: {title}
- 文件: {filename}
- 页数: {page_count}

## 审阅结果

### {dimension} (评分: {rating}/5)
{summary}

#### 优点
- {strength_content} 查看证据：`#evidence-{id}`

#### 缺点
- {weakness_content} 查看证据：`#evidence-{id}`

#### 改进建议
- {suggestion_content} 查看证据：`#evidence-{id}`

## 总评
{overall_verdict}

## 实验指标
| 模型 | 数据集 | 指标 | 值 | 口径 |
|------|--------|------|-----|------|
| {model} | {dataset} | {metric} | {value} | {checkpoint} |

## 实验数据交叉验证
| 指标 | 论文值 | 实验值 | 偏差 | 状态 |
|------|--------|--------|------|------|
| {metric} | {paper_value} | {exp_value} | {diff} | {status} |
```

## 3. 前端设计

### 3.1 报告导出页面 (P08 ReportExportView)

**核心功能:**

- 导出配置：格式选择（Markdown / PDF / DOCX）、语言选择（中文 / 英文）、包含选项
- 生成按钮：提交导出请求
- 导出历史：历史导出列表，含状态、文件大小、下载操作
- 进度显示：生成中显示进度百分比，3 秒轮询
- 下载按钮：状态为 READY 时显示

**交互行为:**

| 交互 | 行为 |
|------|------|
| 点击"生成报告" | 调用 POST /papers/:id/exports |
| 生成中 | 3 秒轮询 GET /exports/:export_id |
| 生成完成 | 状态变为 READY，显示下载按钮 |
| 点击"下载" | 调用 GET /exports/:export_id/download |
| 生成失败 | 显示错误信息 |

## 4. 关键设计决策

| 决策 | 说明 |
|------|------|
| Markdown 优先 | Markdown 为基础格式，PDF/DOCX 通过 reportlab/python-docx 确定性转换生成 |
| 异步生成 | 报告生成可能耗时，使用后台任务 + HTTP 轮询 |
| 确定性输出 | P6.1 已实现：相同输入 → 相同字节 + SHA-256，用于缓存和幂等；P6.2 扩展至 PDF/DOCX |
| 幂等创建 | P6.1 已实现：source_hash/content_hash 部分唯一索引保证同源同内容唯一，不同来源可并存 |
| 安全下载 | P6.1 已实现：size/hash 回读复核、nosniff、attachment、UTF-8 charset、private/no-store；P6.2 扩展至三格式 MIME |
| 禁止字段 | P6.1 已实现：storage_key、content_hash、raw_text、内部路径、tokens 不出现在导出内容中 |
| PDF 确定性 | P6.2 已实现：ReportLab invariant 模式固定 creator/producer/creation/modification/trailer id，STSong-Light 保证中英文可提取，禁止事后二进制替换，PyMuPDF 验证 |
| DOCX 确定性 | P6.2 已实现：固定 core properties，清除 rsid/修订，按 entry 名排序重打包 ZIP，python-docx 验证 |
