# 14. 论文内问答

## 1. 范围

P7.2 为当前登录用户当前论文提供多轮问答。它复用 Paper、Evidence、EmbeddingClient、LLMClient 和 PaperReadingView，不提供开放域、跨论文、联网、流式、消息编辑/删除/分享或向量库。

## 2. 数据与状态

Conversation 只保存 owner、paper 和时间。Turn 冗余 user/paper 以便完整来源图复核，状态为 PENDING→RUNNING→SUCCEEDED/FAILED；同会话同一时刻最多一个活动轮次。Citation 只绑定当前候选且属于当前论文的 Evidence。

## 3. 检索与上下文

后台认领后关闭事务，批量嵌入当前问题和当前论文全部非空 Evidence。向量数量、维度、数值类型、NaN/Inf 与零范数全部验证；按 similarity DESC、page ASC、created_at ASC、id ASC 取 Top-K。历史只取 sequence 更小的最近成功轮次，超过总字符预算时从最旧完整轮次开始删除。

context_hash 包含 conversation/paper/sequence、language、question hash、历史 turn/question/answer hash 和有序候选 Evidence id/text hash。LLM 返回后锁行并按相同规则重新加载和复算；不一致则失败。

## 4. 模型与持久化

title/history/question/Evidence 全部作为不可信内容与 system 指令分隔。模型只返回 answer、grounded、evidence_refs 三字段单 JSON。grounded=true 必须 1～Top-K 个无重复已知 alias；grounded=false 必须零 alias 且说明仅凭当前论文无法确认。

成功时 Citation、answer、grounded、SUCCEEDED 与 conversation.updated_at 同事务提交。任何失败回滚并用独立 Session 把活动轮次写为固定 FAILED，同时清空 context_hash、answer 和 grounded。未知提交结果先回查完整终态。

## 5. API 与页面

5 条 API 见 `09-API接口详细设计.md`。PaperReadingView 的会话和轮次均分页；串行轮询、失败新 id 重试、证据不足样式与 Citation 原文定位均使用独立异步代数，不使用 v-html 或 Web Storage。

## 6. 验收

迁移约束、所有权、幂等/并发、非法向量、预算、prompt/parser、来源变化、原子写入、5 API、双分页、轮询、重试、Citation、竞态与回归全部纳入测试。真实 MaaS/Embedding 不进入自动验收。
