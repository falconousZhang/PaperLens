# 16. 完整管理员系统与不可变审计

## 16.1 概述

P8.1 实现可实际使用的管理员后端、Vue 管理页面、用户角色/状态管理、跨用户内容只读治理和不可变审计。所有管理员操作通过显式 `/admin` API，ADMIN 在普通业务 API 中仍不能绕过 owner。

## 16.2 数据模型

### 16.2.1 admin_audit_logs

| 字段 | 类型 | 约束 |
|------|------|------|
| id | UUID | PK |
| actor_user_id | String(128) | FK users.id RESTRICT, NOT NULL |
| action | String(30) | NOT NULL, CHECK whitelist |
| resource_type | String(20) | NOT NULL, CHECK = 'USER' |
| resource_id | String(128) | NOT NULL |
| reason | String(500) | NOT NULL, CHECK length 8-500, no control chars |
| before_state | JSONB | NOT NULL, CHECK only role/status keys |
| after_state | JSONB | NOT NULL, CHECK only role/status keys |
| created_at | DateTime(tz) | NOT NULL, server_default=now() |

CHECK 约束：
- action IN ('ADMIN_BOOTSTRAPPED', 'USER_ROLE_CHANGED', 'USER_STATUS_CHANGED')
- resource_type = 'USER'
- length(reason) BETWEEN 8 AND 500, no control chars (regex)
- before_state/after_state: only 'role' and/or 'status' keys, values are strings

索引：
- idx_audit_actor (actor_user_id)
- idx_audit_resource (resource_type, resource_id)
- idx_audit_action (action)
- idx_audit_created (created_at DESC, id DESC)

PostgreSQL trigger: `prevent_audit_modification` — RAISE EXCEPTION on UPDATE or DELETE.

### 16.2.2 ORM 模型 AdminAuditLog

对应 admin_audit_logs 表，无 UPDATE/DELETE 方法。应用层只做 INSERT 和 SELECT。

## 16.3 管理员授权

1. 复用 `require_admin` 依赖：无认证 401，已认证 USER 403
2. DISABLED 用户、session 撤销、refresh replay 由 P3.5 服务端状态拒绝
3. 前端路由守卫只改善体验，后端始终权威

## 16.4 CLI admin-bootstrap

```
python -m paperlens.cli admin-bootstrap --user-id <UUID> --reason <text>
```

- 只允许把已存在、ACTIVE 的 USER 提升为首个 ADMIN
- 仅当数据库没有 ACTIVE ADMIN 时成功
- 以目标用户 id 作为 actor_user_id
- 创建 ADMIN_BOOTSTRAPPED 审计
- 撤销旧 session
- 同事务完成
- 已有 ACTIVE ADMIN、目标非法/不存在/禁用、并发第二次执行都安全失败

## 16.5 用户变更 PATCH

`PATCH /api/v1/admin/users/{user_id}`

1. 只接受可选 role USER|ADMIN、可选 status ACTIVE|DISABLED 和必填 reason；extra=forbid
2. role/status 至少一个；相同值返回 200/changed=false 不写审计
3. FOR UPDATE 锁定 ACTIVE ADMIN 集合和目标用户
4. 禁止管理员自降级或自禁用
5. 任何提交后至少保留一个 ACTIVE ADMIN
6. 每个实际变化字段各写一条 audit；before/after 来自锁定后的数据库
7. 角色或状态变化后撤销目标全部活动 AuthSession
8. 禁用时使未使用 PasswordResetToken 失效
9. 两管理员并发互相降级/禁用时最多一个成功，另一个 409

## 16.6 API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /admin/dashboard | 聚合计数 |
| GET | /admin/users | 用户列表（role/status/q 筛选） |
| GET | /admin/users/{user_id} | 用户详情 |
| PATCH | /admin/users/{user_id} | 角色状态变更 |
| GET | /admin/papers | 跨用户论文只读 |
| GET | /admin/tasks | 跨用户任务只读 |
| GET | /admin/exports | 跨用户报告只读 |
| GET | /admin/audit-logs | 审计日志列表 |

所有列表统一分页，按 created_at DESC/id DESC 稳定排序。只读查询使用有限列投影。

## 16.7 前端设计

AdminDashboardView 四区域：
1. 总览：固定计数卡
2. 用户：列表/详情/角色状态变更确认对话框（reason 输入）
3. 内容：论文/任务/报告三子标签（只读）
4. 审计：审计日志列表（只读）

安全要求：
- 路由守卫仅 ADMIN 可见
- 401 清理认证状态，403 不泄露数据
- 确认对话框明确目标与后果
- Vue 转义插值，禁止 v-html/Web Storage/token URL
- 前端也禁止自降级/自禁用按钮
