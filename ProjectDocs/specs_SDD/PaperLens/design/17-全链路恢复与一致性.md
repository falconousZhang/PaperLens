# 17 - 全链路恢复与一致性

## 1. 概述

P8.2 为 FastAPI BackgroundTasks 增加启动时的保守恢复收口，并统一用户端轮询。它不是持久化任务队列；无法证明可安全重放的任务必须进入固定 FAILED，再由用户从原入口重试。

## 2. 恢复状态矩阵

| 实体 | 陈旧判定 | 可恢复动作 | 安全失败动作 |
|------|----------|------------|--------------|
| Paper PROCESSING | updated_at < cutoff | 无 | 缺少可靠执行代次，固定 FAILED |
| AnalysisTask PENDING | created_at < cutoff | METRIC_EXTRACTION / EXPERIMENT_ANALYSIS 重新派发 | REVIEW 缺少原始 options，固定 FAILED |
| AnalysisTask RUNNING | started_at 为空或早于 cutoff | 已有完整结果则 SUCCEEDED；指标/实验无结果则复位并派发 | REVIEW 无结果固定 FAILED |
| LearningExplanation PENDING/RUNNING | created_at 或 started_at 早于 cutoff | 复位为 PENDING，调用现有原子 claim 执行器 | 执行器验证来源失败后固定 FAILED |
| PaperQATurn PENDING/RUNNING | created_at 或 started_at 早于 cutoff | 复位为 PENDING，调用现有原子 claim 执行器 | 执行器验证上下文失败后固定 FAILED |
| ExportReport PENDING/GENERATING | created_at < cutoff | 无 | 生成 bytes 未持久化，固定 FAILED |

## 3. RecoveryService

配置使用 `PAPERLENS_` 前缀：

- `RECOVERY_ENABLED`：默认 true。
- `RECOVERY_STALE_SECONDS`：默认 300，范围 1～86400。
- `RECOVERY_BATCH_SIZE`：默认 50，范围 1～1000。

启动流程：

1. FastAPI lifespan 调用 `run_recovery()`。
2. RecoveryService 执行 `pg_try_advisory_xact_lock`；锁繁忙立即跳过。
3. 按 Paper → AnalysisTask → LearningExplanation → PaperQATurn → ExportReport 扫描。
4. 每类按 created_at/id 升序并限制 batch_size，使用 `FOR UPDATE SKIP LOCKED`。
5. 扫描事务只复位、失败或登记派发，然后提交并释放锁。
6. 提交后才启动 daemon worker，外部推理和文件处理不持有扫描事务。

现有指标、实验、学习和问答执行器均以 PENDING 条件更新或行锁完成原子 claim。重复派发最多产生一个实际执行者，不重复持久化结果。审阅执行器补充 PENDING claim、终态前行锁和既有结果检查，迟到 worker 不覆盖终态。

## 4. 前端一致性

`frontend/src/composables/usePolling.ts` 提供：

- 默认 3 秒间隔。
- 同一实例最多一个在途请求。
- generation 隔离与停止后旧响应失效。
- 终态自动停止，组件卸载自动清理。
- 401 跳转登录并携带当前 redirect。
- 未知错误只交给页面显示固定公开文案。

PaperDetailView、ReviewResultView、MetricAnalysisView、ExperimentDataView、ReportExportView 与 PaperReadingView 的学习解释和问答均实际复用该 composable。ExperimentDataView 通过 TaskDetail 可空 `experiment_file_id` 恢复活动任务对应的文件上下文。

## 5. API 与数据模型

P8.2 不新增表、字段、索引、迁移或路由。既有 TaskDetail / TaskListItem 响应增加 AnalysisTask 已存在的可空 `experiment_file_id` 白名单字段；除 EXPERIMENT_ANALYSIS 外为 null。不公开 storage_key、文件哈希、正文或模型内容。

## 6. 日志白名单

恢复日志只记录 stage、entity_type、entity_id、task_type、action、异常类型和计数。不记录 email、论文/问题/笔记/模型内容、路径、hash、token、SQL 或底层错误文本。
