## P3.2 码道独立审查修正

码道初版后端全量 182 项可通过，但独立审查发现：配置中的 SecretStr 被直接格式化为 `**********`，真实华为鉴权会失败；外部 Embedding/LLM 调用期间持有数据库事务；批处理未复用连接；响应对象、index 和构造配置校验不完整；Mock 分词不支持无空格中文；检索层 SQL 与外部调用耦合。以上均已直接修复，并补齐首批/查询/后续 batch 失败、密钥脱敏和全批次原子回滚测试。

## P3.3 码道独立审查修正

码道初版 P3.3 定向 55 项和后端全量 259 项可通过，但未覆盖 Huawei 适配器到真实审阅任务的成功绑定、首维/第二维失败回滚和 transport 事务断言。实现还会接受多 choice 歧义响应，错误类型参数可能泄漏为底层异常，非有限/越界配置未被直接构造路径拒绝，未知 finish_reason 值会进入异常文本。码道已直接修复这些边界，补齐 18 项定向测试，并把误报的 16 端点校准为 12 条 `/api/v1` 业务路由。

## 真实 GLM 审阅兼容修复

用户首次通过真实 GLM-5.2 审阅 BVG.pdf 时，模型返回了被标准 `json` Markdown 围栏包裹的完整单一 JSON，旧解析器按预期拒绝围栏，任务安全进入 FAILED 且三类审阅结果表均无本任务数据。华为 MaaS V2 公开契约未提供 `response_format=json_object`，因此 码道仅兼容单层标准 JSON/无语言围栏，并继续拒绝前后附文、非 JSON 标签、嵌套/多围栏和所有 Schema 违规内容。

定位日志同时暴露 SQLAlchemy `echo` 会记录论文表格原文和绑定参数。数据库引擎现固定 `echo=false`、`hide_parameters=true`，不再由应用 debug 开启 SQL 参数回显。修复后 138 项审阅/Huawei 定向与 435 项后端全量全部通过、0 skipped；未自动发起新的真实计费审阅。
