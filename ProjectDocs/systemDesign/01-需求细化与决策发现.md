# 需求细化与决策发现

## 文档信息

- **项目名称**: PaperLens
- **文档版本**: v1.0
- **创建日期**: 2026-07-13
- **最后更新**: 2026-07-13

## 1. 五个为什么分析

### 1.1 核心问题：人工审稿耗时过长

**问题链分析**：

1. **为什么人工审稿耗时 2-4 小时？**
   - 审稿人需要反复翻阅论文定位支撑证据

2. **为什么定位证据如此耗时？**
   - PDF 论文缺乏结构化索引，无法快速跳转到相关段落

3. **为什么缺乏结构化索引？**
   - PDF 是面向排版的格式，丢失了语义结构信息

4. **为什么丢失语义结构后只能人工处理？**
   - 现有工具无法自动将 PDF 内容重建为可检索的语义结构

5. **为什么没有自动化工具完成语义重建与检索？**
   - 学术论文的章节结构、表格、指标具有领域特殊性，通用文档工具无法精准处理

**根本原因**：学术论文 PDF 缺乏机器可读的语义结构，而通用文档工具不具备学术领域的结构解析能力，导致审稿人只能依赖人工定位证据，造成大量时间浪费。

### 1.2 核心问题：AI 审稿意见缺乏可信度

**问题链分析**：

1. **为什么 AI 审稿意见可信度低？**
   - AI 生成的审稿意见常出现幻觉，无法追溯到论文原文

2. **为什么会出现幻觉？**
   - 大模型生成文本时缺乏对原文的精确引用约束

3. **为什么缺乏精确引用约束？**
   - 大模型以概率方式生成文本，天然不保证与源文档的事实一致性

4. **为什么不能在生成后校验？**
   - 缺乏自动化的原文回溯与证据绑定机制

5. **为什么缺乏证据绑定机制？**
   - 现有 AI 审稿工具将 LLM 视为黑盒，未在架构层面强制 Evidence 绑定

**根本原因**：现有 AI 审稿工具在架构上未强制要求每条结论绑定原文 Evidence，LLM 作为概率模型天然产生幻觉，需要系统级约束而非依赖模型自觉。

### 2.2 隐式假设与决策

#### 假设1：PDF 包含可提取文本
**假设**：用户上传的 PDF 论文包含可提取的文本层，而非扫描图像。
**风险**：部分老旧论文或扫描件无文本层，MVP 阶段无法处理，可能导致用户困惑。
**决策**：MVP 仅支持包含可提取文本的 PDF，上传时校验文本可提取性，不可提取时返回明确提示。扫描型 PDF / OCR 放入后续版本。

#### 假设2：论文语言以英文为主
**假设**：MVP 阶段处理的学术论文主要为英文论文。
**风险**：中文论文的分块和指标提取效果可能不佳，影响部分用户体验。
**决策**：MVP 聚焦英文论文场景，中文支持作为 P2 功能后续评估。

#### 假设3：单篇论文独立审阅
**假设**：用户每次审阅一篇论文，不需要跨论文对比。
**风险**：部分用户有对比审阅需求，MVP 无法满足。
**决策**：MVP 仅支持单篇论文审阅，多论文对比审阅（F14）列为加分功能。

#### 假设4：LLM 推理接口可用且稳定
**假设**：ModelArts 推理接口或替代 LLM 服务的可用性和响应时间满足用户体验要求。
**风险**：LLM 服务不可用或延迟过高时，审阅功能无法使用。
**决策**：通过 LLMClient 接口抽象实现 LLM 可替换性，默认提供 MockLLMClient 用于演示和测试，确保无云端密钥也可完整运行。

### 2.3 技术决策假设

#### 决策1：后端技术栈选择
**决策**：Python (FastAPI) + 向量数据库（Milvus/Chroma）
**理由**：
- Python 生态在 NLP、PDF 解析、数据分析领域库最丰富（pdfplumber、pandas、numpy）
- FastAPI 原生支持异步和类型提示，适合 I/O 密集型任务
- 向量数据库为 RAG 架构的核心组件，Milvus/Chroma 与 Python 生态集成良好

**权衡**：
- 优势：开发效率高，学术领域库支持完善，团队技能匹配
- 劣势：Python 高并发性能不如 Go/Rust，需通过异步和任务队列弥补

#### 决策2：部署方式
**决策**：容器化部署（Docker Compose），面向华为云 ModelArts 集成
**理由**：
- Docker Compose 便于本地开发和演示环境快速搭建
- ModelArts 为 LLM 推理的指定平台，需适配其接口规范
- 容器化保证环境一致性，简化部署流程

**权衡**：
- 优势：环境一致性好，部署灵活，便于 CI/CD
- 劣势：Docker Compose 不适合大规模生产部署，生产环境需迁移至 Kubernetes

## 3. 关键决策点

### 3.1 业务决策点

#### 决策点1：审阅结论的 Evidence 绑定粒度
**问题**：每条审阅结论（ReviewFinding）应绑定到什么粒度的原文证据？
**选项**：
- A：段落级绑定——Evidence 为一个完整段落
- B：句子级绑定——Evidence 为一个或多个句子

**决策**：采用 A 方案（段落级绑定）
**理由**：
- 段落级上下文更完整，避免断章取义
- 句子级切分增加 LLM 处理复杂度和幻觉风险
- 段落级绑定与文本分块（F04）的粒度一致，实现更简洁

#### 决策点2：指标口径统一的自动化程度
**问题**：对 final/max/mean/best 等不同口径的实验指标，系统应自动统一还是仅标注？
**选项**：
- A：自动统一——将所有指标转换为统一口径
- B：仅标注口径——识别并标注口径差异，由用户判断

**决策**：采用 B 方案（仅标注口径）
**理由**：
- 不同口径间的转换需要领域知识，自动转换可能引入错误
- 标注口径已足够解决"口径混乱"痛点，用户可据此判断
- 自动统一口径可作为后续增强功能，降低 MVP 风险

### 3.2 技术决策点

#### 决策点3：RAG 检索策略
**问题**：论文证据检索应采用何种 RAG 策略？
**选项**：
- A：纯向量检索——基于 Embedding 相似度检索
- B：混合检索——向量检索 + 关键词检索（BM25）融合

**决策**：选择 B 方案（混合检索）
**理由**：
- 学术论文包含大量专业术语和指标名称，关键词检索可精准匹配
- 纯向量检索对术语精确匹配能力弱，可能遗漏关键证据
- 混合检索兼顾语义相似性和关键词精确性，提升 Evidence 召回率

## 6. 决策简报

### 6.1 核心决策总结

| 决策领域 | 决策内容 | 理由 | 风险 |
|----------|----------|------|------|
| Evidence 绑定粒度 | 段落级绑定 | 上下文完整，与分块粒度一致，降低幻觉 | 段落可能包含冗余信息 |
| 指标口径处理 | 仅标注口径，不自动统一 | 避免自动转换引入错误，降低 MVP 风险 | 用户需自行判断口径差异 |
| RAG 检索策略 | 混合检索（向量 + BM25） | 兼顾语义相似性和术语精确匹配 | 实现复杂度高于纯向量检索 |
| LLM 集成方式 | LLMClient 接口抽象 + MockLLMClient | 无密钥可演示，支持 LLM Provider 切换 | MockLLMClient 生成质量有限 |
| 统计计算方式 | 确定性 Python 代码计算，LLM 不参与 | 保证数值准确性，消除 LLM 计算幻觉 | 需为每种统计口径编写规则代码 |

### 6.2 关键约束

1. **时间约束**：核心审阅 MVP 先交付 F01-F10；完整项目验收额外要求 F21 用户账号与权限、F22 管理员系统
2. **预算约束**：依赖华为云 ModelArts 推理服务，需控制 LLM 调用成本
3. **团队约束**：团队对 LLM 集成经验有限，需通过 MockLLMClient 降低开发门槛
4. **性能约束**：论文审阅为异步任务，LLM 推理延迟通过 HTTP 轮询通知，暂不实现 WebSocket
5. **安全约束**：文件类型检查、50MB 大小限制、路径穿越防护、用户数据严格隔离、超期自动清理

### 6.3 成功标准

1. **功能完整性**：核心业务 F01-F13 可运行，必做平台能力 F21 用户账号与权限、F22 管理员系统完整可用
2. **性能达标**：单篇论文（50 页以内）从上传到审阅报告生成不超过 5 分钟
3. **用户接受度**：审阅结论 100% 绑定 Evidence，用户可验证每条意见的原文依据
4. **数据准确性**：实验指标提取准确率 >= 90%，统计口径标注准确率 >= 85%
5. **系统稳定性**：MockLLMClient 支持无密钥完整演示，LLM Provider 切换不影响核心流程

### 6.4 新增必做需求：用户体系与管理员系统

P3.5 已用统一 Bearer JWT + AuthSession/User 依赖替换运行时 `demo_user_id`；`demo-user` 仅是 disabled legacy 数据占位。建设状态如下：

1. **P3.5 用户与权限后端（已完成）**：注册、登录、退出、访问/刷新令牌、轮换/撤销、密码修改和找回、个人资料、账号禁用/锁定，以及 USER/ADMIN RBAC 基础。
2. **真实资源归属（已完成）**：现有论文、任务、审阅从认证上下文取得 user_id；后续指标、实验和报告沿用同一边界。
3. **用户端认证页面（已完成）**：注册、登录、找回/重置密码、个人中心和受保护路由已在 P3.5 交付。
4. **P7 管理员系统**：独立管理布局、运行概览、用户/角色/账号状态管理、论文与任务管理、异常处理和审计日志查询。
5. **安全边界**：密码采用可靠自适应哈希；短时访问令牌与可撤销刷新令牌；登录限流与失败锁定；管理员操作服务端鉴权并写入审计日志；禁止硬编码默认管理员凭据。
6. **华为云边界**：PaperLens 业务用户与管理员由应用自身管理；华为云 IAM 只用于云资源和服务身份，不代替产品用户系统。

## 8. P4.1 决策补充

1. 指标提取采用完全离线、确定性规则，不用 LLM 猜测候选或数值。
2. 百分号统一为 0～1；非百分比指标允许有限负数，NaN/Infinity、范围和均值±误差拒绝。
3. Checkpoint 只接受 caption、行标签或 Evidence 的明确完整关键词；冲突和无证据都为 UNKNOWN。
4. 每条记录只能绑定表格行或 Evidence；模型和数据集只从明确语义列提取。
5. P4.1 已交付后端；P4.2 已交付指标前端和完整任务交互。CSV/Excel、报告和完整管理员系统仍按后续阶段推进。

## P4.3 运行配置决策

- 华为云 MaaS LLM 适配器与运行开关分离：适配器已实现不等于真实账号联调完成。

- 配置检查完全离线；真实烟测必须带 `--confirm-billable`，且由用户明确确认后手工执行。

## 9. P5.1 实验文件决策

1. P5.1 只完成 CSV/XLSX/XLS 安全上传、可信结构解析、列表和详情，不创建 AnalysisTask 或 ExperimentResult，不计算统计值。
2. 上传按固定块写入随机临时文件；解析器只接收服务端路径和已确认类型，完全离线且不依赖 LLM/Embedding。
3. `columns_info` 采用 version=1 严格对象，只保存列名、规范 dtype、nullable 和 null_count，不保存样本或数据行。
4. XLSX 先做 ZIP 容器安全检查，再交给 openpyxl；XLS 只由 xlrd 读取缓存值，不执行宏、DDE、外链或网络。
5. 完整文件哈希和对象 key 仅内部使用；同一用户/论文/哈希幂等，并发由 008 唯一约束收口。
6. 用户隔离沿用 P3.5：user_id 只来自认证上下文，ADMIN 不获得跨用户实验资源旁路权限。
7. P5.2 只实现统计摘要；指标交叉验证和实验数据前端留到 P5.3，删除/下载继续单独设计。
