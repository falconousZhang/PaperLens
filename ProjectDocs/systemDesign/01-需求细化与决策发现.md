# 需求细化与决策发现

## 文档信息

- **项目名称**: PaperLens
- **文档版本**: v1.0
- **创建日期**: 2026-07-13
- **最后更新**: 2026-07-13

## 1. 五个为什么分析

### 1.1 核心问题：人工审稿耗时过长

**问题链分析**：

1. **为什么人工审稿耗时 2-4 小时？**
   - 审稿人需要反复翻阅论文定位支撑证据

2. **为什么定位证据如此耗时？**
   - PDF 论文缺乏结构化索引，无法快速跳转到相关段落

3. **为什么缺乏结构化索引？**
   - PDF 是面向排版的格式，丢失了语义结构信息

4. **为什么丢失语义结构后只能人工处理？**
   - 现有工具无法自动将 PDF 内容重建为可检索的语义结构

5. **为什么没有自动化工具完成语义重建与检索？**
   - 学术论文的章节结构、表格、指标具有领域特殊性，通用文档工具无法精准处理

**根本原因**：学术论文 PDF 缺乏机器可读的语义结构，而通用文档工具不具备学术领域的结构解析能力，导致审稿人只能依赖人工定位证据，造成大量时间浪费。

### 1.2 核心问题：AI 审稿意见缺乏可信度

**问题链分析**：

1. **为什么 AI 审稿意见可信度低？**
   - AI 生成的审稿意见常出现幻觉，无法追溯到论文原文

2. **为什么会出现幻觉？**
   - 大模型生成文本时缺乏对原文的精确引用约束

3. **为什么缺乏精确引用约束？**
   - 大模型以概率方式生成文本，天然不保证与源文档的事实一致性

4. **为什么不能在生成后校验？**
   - 缺乏自动化的原文回溯与证据绑定机制

5. **为什么缺乏证据绑定机制？**
   - 现有 AI 审稿工具将 LLM 视为黑盒，未在架构层面强制 Evidence 绑定

**根本原因**：现有 AI 审稿工具在架构上未强制要求每条结论绑定原文 Evidence，LLM 作为概率模型天然产生幻觉，需要系统级约束而非依赖模型自觉。

### 2.2 隐式假设与决策

#### 假设1：PDF 包含可提取文本
**假设**：用户上传的 PDF 论文包含可提取的文本层，而非扫描图像。
**风险**：部分老旧论文或扫描件无文本层，MVP 阶段无法处理，可能导致用户困惑。
**决策**：MVP 仅支持包含可提取文本的 PDF，上传时校验文本可提取性，不可提取时返回明确提示。扫描型 PDF / OCR 放入后续版本。

#### 假设2：论文语言以英文为主
**假设**：MVP 阶段处理的学术论文主要为英文论文。
**风险**：中文论文的分块和指标提取效果可能不佳，影响部分用户体验。
**决策**：MVP 聚焦英文论文场景，中文支持作为 P2 功能后续评估。

#### 假设3：单篇论文独立审阅
**假设**：用户每次审阅一篇论文，不需要跨论文对比。
**风险**：部分用户有对比审阅需求，MVP 无法满足。
**决策**：MVP 仅支持单篇论文审阅，多论文对比审阅（F14）列为加分功能。

#### 假设4：LLM 推理接口可用且稳定
**假设**：ModelArts 推理接口或替代 LLM 服务的可用性和响应时间满足用户体验要求。
**风险**：LLM 服务不可用或延迟过高时，审阅功能无法使用。
**决策**：通过 LLMClient 接口抽象实现 LLM 可替换性，默认提供 MockLLMClient 用于演示和测试，确保无云端密钥也可完整运行。

### 2.3 技术决策假设

#### 决策1：后端技术栈选择
**决策**：Python (FastAPI) + 向量数据库（Milvus/Chroma）
**理由**：
- Python 生态在 NLP、PDF 解析、数据分析领域库最丰富（pdfplumber、pandas、numpy）
- FastAPI 原生支持异步和类型提示，适合 I/O 密集型任务
- 向量数据库为 RAG 架构的核心组件，Milvus/Chroma 与 Python 生态集成良好

**权衡**：
- 优势：开发效率高，学术领域库支持完善，团队技能匹配
- 劣势：Python 高并发性能不如 Go/Rust，需通过异步和任务队列弥补

#### 决策2：部署方式
**决策**：容器化部署（Docker Compose），面向华为云 ModelArts 集成
**理由**：
- Docker Compose 便于本地开发和演示环境快速搭建
- ModelArts 为 LLM 推理的指定平台，需适配其接口规范
- 容器化保证环境一致性，简化部署流程

**权衡**：
- 优势：环境一致性好，部署灵活，便于 CI/CD
- 劣势：Docker Compose 不适合大规模生产部署，生产环境需迁移至 Kubernetes

## 3. 关键决策点

### 3.1 业务决策点

#### 决策点1：审阅结论的 Evidence 绑定粒度
**问题**：每条审阅结论（ReviewFinding）应绑定到什么粒度的原文证据？
**选项**：
- A：段落级绑定——Evidence 为一个完整段落
- B：句子级绑定——Evidence 为一个或多个句子

**决策**：采用 A 方案（段落级绑定）
**理由**：
- 段落级上下文更完整，避免断章取义
- 句子级切分增加 LLM 处理复杂度和幻觉风险
- 段落级绑定与文本分块（F04）的粒度一致，实现更简洁

#### 决策点2：指标口径统一的自动化程度
**问题**：对 final/max/mean/best 等不同口径的实验指标，系统应自动统一还是仅标注？
**选项**：
- A：自动统一——将所有指标转换为统一口径
- B：仅标注口径——识别并标注口径差异，由用户判断

**决策**：采用 B 方案（仅标注口径）
**理由**：
- 不同口径间的转换需要领域知识，自动转换可能引入错误
- 标注口径已足够解决"口径混乱"痛点，用户可据此判断
- 自动统一口径可作为后续增强功能，降低 MVP 风险

### 3.2 技术决策点

#### 决策点3：RAG 检索策略
**问题**：论文证据检索应采用何种 RAG 策略？
**选项**：
- A：纯向量检索——基于 Embedding 相似度检索
- B：混合检索——向量检索 + 关键词检索（BM25）融合

**决策**：选择 B 方案（混合检索）
**理由**：
- 学术论文包含大量专业术语和指标名称，关键词检索可精准匹配
- 纯向量检索对术语精确匹配能力弱，可能遗漏关键证据
- 混合检索兼顾语义相似性和关键词精确性，提升 Evidence 召回率

## 6. 决策简报

### 6.1 核心决策总结

| 决策领域 | 决策内容 | 理由 | 风险 |
|----------|----------|------|------|
| Evidence 绑定粒度 | 段落级绑定 | 上下文完整，与分块粒度一致，降低幻觉 | 段落可能包含冗余信息 |
| 指标口径处理 | 仅标注口径，不自动统一 | 避免自动转换引入错误，降低 MVP 风险 | 用户需自行判断口径差异 |
| RAG 检索策略 | 混合检索（向量 + BM25） | 兼顾语义相似性和术语精确匹配 | 实现复杂度高于纯向量检索 |
| LLM 集成方式 | LLMClient 接口抽象 + MockLLMClient | 无密钥可演示，支持 LLM Provider 切换 | MockLLMClient 生成质量有限 |
| 统计计算方式 | 确定性 Python 代码计算，LLM 不参与 | 保证数值准确性，消除 LLM 计算幻觉 | 需为每种统计口径编写规则代码 |

### 6.2 关键约束

1. **时间约束**：核心审阅 MVP 先交付 F01-F10；完整项目验收额外要求 F21 用户账号与权限、F22 管理员系统
2. **预算约束**：依赖华为云 ModelArts 推理服务，需控制 LLM 调用成本
3. **团队约束**：团队对 LLM 集成经验有限，需通过 MockLLMClient 降低开发门槛
4. **性能约束**：论文审阅为异步任务，LLM 推理延迟通过 HTTP 轮询通知，暂不实现 WebSocket
5. **安全约束**：文件类型检查、50MB 大小限制、路径穿越防护、用户数据严格隔离、超期自动清理

### 6.3 成功标准

1. **功能完整性**：核心业务 F01-F13 可运行，必做平台能力 F21 用户账号与权限、F22 管理员系统完整可用
2. **性能达标**：单篇论文（50 页以内）从上传到审阅报告生成不超过 5 分钟
3. **用户接受度**：审阅结论 100% 绑定 Evidence，用户可验证每条意见的原文依据
4. **数据准确性**：实验指标提取准确率 >= 90%，统计口径标注准确率 >= 85%
5. **系统稳定性**：MockLLMClient 支持无密钥完整演示，LLM Provider 切换不影响核心流程

### 6.4 新增必做需求：用户体系与管理员系统

P3.5 已用统一 Bearer JWT + AuthSession/User 依赖替换运行时 `demo_user_id`；`demo-user` 仅是 disabled legacy 数据占位。建设状态如下：

1. **P3.5 用户与权限后端（已完成）**：注册、登录、退出、访问/刷新令牌、轮换/撤销、密码修改和找回、个人资料、账号禁用/锁定，以及 USER/ADMIN RBAC 基础。
2. **真实资源归属（已完成）**：现有论文、任务、审阅从认证上下文取得 user_id；后续指标、实验和报告沿用同一边界。
3. **用户端认证页面（已完成）**：注册、登录、找回/重置密码、个人中心和受保护路由已在 P3.5 交付。
4. **P7 管理员系统**：独立管理布局、运行概览、用户/角色/账号状态管理、论文与任务管理、异常处理和审计日志查询。
5. **安全边界**：密码采用可靠自适应哈希；短时访问令牌与可撤销刷新令牌；登录限流与失败锁定；管理员操作服务端鉴权并写入审计日志；禁止硬编码默认管理员凭据。
6. **华为云边界**：PaperLens 业务用户与管理员由应用自身管理；华为云 IAM 只用于云资源和服务身份，不代替产品用户系统。

## 8. P4.1 决策补充

1. 指标提取采用完全离线、确定性规则，不用 LLM 猜测候选或数值。
2. 百分号统一为 0～1；非百分比指标允许有限负数，NaN/Infinity、范围和均值±误差拒绝。
3. Checkpoint 只接受 caption、行标签或 Evidence 的明确完整关键词；冲突和无证据都为 UNKNOWN。
4. 每条记录只能绑定表格行或 Evidence；模型和数据集只从明确语义列提取。
5. P4.1 已交付后端；P4.2 已交付指标前端和完整任务交互。CSV/Excel、报告和完整管理员系统仍按后续阶段推进。

## P4.3 运行配置决策

- 华为云 MaaS LLM 适配器与运行开关分离：适配器已实现不等于真实账号联调完成。

- 配置检查完全离线；真实烟测必须带 `--confirm-billable`，且由用户明确确认后手工执行。

## 9. P5.1 实验文件决策

1. P5.1 只完成 CSV/XLSX/XLS 安全上传、可信结构解析、列表和详情，不创建 AnalysisTask 或 ExperimentResult，不计算统计值。
2. 上传按固定块写入随机临时文件；解析器只接收服务端路径和已确认类型，完全离线且不依赖 LLM/Embedding。
3. `columns_info` 采用 version=1 严格对象，只保存列名、规范 dtype、nullable 和 null_count，不保存样本或数据行。
4. XLSX 先做 ZIP 容器安全检查，再交给 openpyxl；XLS 只由 xlrd 读取缓存值，不执行宏、DDE、外链或网络。
5. 完整文件哈希和对象 key 仅内部使用；同一用户/论文/哈希幂等，并发由 008 唯一约束收口。
6. 用户隔离沿用 P3.5：user_id 只来自认证上下文，ADMIN 不获得跨用户实验资源旁路权限。
7. P5.2 只实现统计摘要；P5.3a 已实现指标交叉验证后端，实验数据前端留到 P5.3b，删除/下载继续单独设计。

## 10. P5.2 统计摘要决策

1. 统计任务只接受当前用户自己的 ExperimentFile，论文必须仍为 PARSED；ADMIN 不获得他人资源旁路。
2. 执行前后均复核存储文件 SHA-256，并重新执行 P5.1 容器安全与完整结构解析；数据库元数据任一差异均安全失败。
3. 数据行按路径逐行读取，只保留数值列的紧凑 float 数组用于精确 median，不保存原始行、字符串样本或 DataFrame。
4. mean/stddev 使用 Welford，stddev 为样本标准差；拒绝 NaN、Infinity、计算溢出和超 JavaScript 安全范围的整数。
5. 任务、ExperimentResult 和 SUCCEEDED 在同一事务提交；失败结果为 0，commit 结果未知时重新查询，不删除已提交结果。
6. P5.3a 只实现 MetricRecord 交叉验证后端，P5.3b 再实现实验数据页面，不合并成额外返工轮次。

## 11. P5.3a 指标交叉验证决策

1. 指标名只按 NFKC、casefold 和 Unicode 字母数字过滤确定性匹配，不增加语义别名、翻译或模糊相似度。
2. 每个规范指标名必须对应唯一 MetricRecord 和唯一数值列；重复论文指标、缺列或重复列均诚实标记 UNVERIFIABLE。
3. 只允许 MEAN 使用实验列 mean、MAX 使用 max；BEST、FINAL、LAST、UNKNOWN 不猜测统计口径。
4. 差值固定为 experiment_value - paper_value；零论文值的 relative_diff 为 null，所有公开数字必须有限。
5. 结果行加锁后原子写入既有 metric_comparisons；同源幂等、异源 409，提交结果未知时由新会话只读回查。
6. 交叉验证不读取实验原文件、数据行、MetricRecord.raw_text、PaperTable.raw_text/structured_data 或 Evidence 正文，也不构造模型客户端。

## 12. P5.3b 实验数据前端决策

4. 已有 metric_comparisons 必须直接显示并锁定 metric_task_id，不重复提交或覆盖来源；没有结果时默认选择最新成功指标任务。

## 13. P6.1 Markdown 导出报告决策

## 15. 产品方向校正：个人论文阅读学习助手（2026-07-15）

### 15.1 根本问题

此前设计把“替用户形成审稿判断”作为主线，偏离了用户真正目标：在个人学习过程中更快读懂论文、理解难点、核实结论并沉淀知识。已完成的审阅、指标和实验能力不是废弃功能，而应作为阅读工作台中的“批判性阅读”和“实验理解”工具。

### 15.2 已确认决策

1. 产品主流程改为：`上传论文 → 阅读工作台 → 章节/页面定位 → 总结/解释/翻译 → 论文内问答 → 笔记/知识卡 → 复习/导出`。
2. P7.1 原管理员后端轮次被“论文阅读工作台与证据化学习解释”替换；不增加总轮数。
3. 结构化审阅改称“批判性阅读”，保留全部既有数据、API 和页面，不做破坏性迁移。
4. 指标提取、实验统计与交叉验证定位为理解实验和核对论文结论的高级工具。
5. P7.2 实现论文内多轮问答；P7.3 实现高亮、书签、笔记、知识卡、论文库组织和学习进度。
6. 完整登录注册和管理员系统仍是最终交付要求；管理员后端、前端与不可变审计合并到 P8.1，不取消、不增加轮次。
7. P8.2～P8.4 依次用于全链路与恢复验收、性能可靠性、华为云部署和综合安全收口。

### 15.3 P7.1 成功标准

- 用户可从论文详情进入独立阅读工作台，并在目录、正文和学习助手之间持续保持当前上下文。
- 用户可对服务端确认的章节、页面或 Evidence 发起总结、解释和翻译，不允许客户端提交任意伪造论文正文。
- 每个成功结果至少绑定一个真实 Evidence；未知引用、跨论文引用或证据不足时不得公开半可信答案。
- 默认 Mock 可完整演示；配置 Huawei MaaS 时复用既有 LLMClient，自动测试不联网、不读取密钥。
- 所有历史 P2～P6 能力和验收结论保持真实，不把规划中的学习功能写成已完成。

### 15.4 P7.1 实现结论

上述成功标准已于 2026-07-15 全部实现。PaperReadingView、3 条 learning API、LearningExplanation/Citation、来源双重复核、严格术语/Citation 契约和学习历史均已通过独立验收。实际基线为 Alembic 014、37 条 API、19 张 ORM 应用表、后端 866 passed、前端 183 passed；下一阶段为 P7.2。

## 16. P7.2 当前论文多轮问答决策

1. 问答只在当前登录用户拥有且状态为 PARSED 的当前论文内进行；USER 与 ADMIN 在普通业务 API 中遵循相同所有权边界。
2. 会话是空容器，客户端不能指定标题、用户、论文正文、Evidence、prompt 或模型参数。问题只提交去空白后的文本、zh/en 和 UUID4 幂等键。
3. 服务端只从当前论文非空 Evidence 做即时 Embedding 余弦 Top-K；外部 Embedding/LLM 期间不持有数据库事务。历史只纳入同会话最近成功轮次，并按完整轮次执行数量和字符预算。
4. `grounded=true` 必须绑定至少一个同论文 Citation；`grounded=false` 必须零 Citation，并明确说明仅凭当前论文无法确认。开放域、跨论文和外部知识补足均不允许。
5. 活动轮次由数据库部分唯一索引收口；生成前写入完整上下文哈希，模型返回后重新读取会话、论文、历史和候选 Evidence 复算，来源变化则固定失败。
6. P7.2 与 P7.3 均已实现并经 码道独立验收；下一固定轮次 P8.1 完成管理员后端、管理页面、用户角色/状态与不可变审计。

## 17. P7.3 个人学习沉淀与论文库决策

1. 个人学习数据（高亮、书签、笔记、知识卡、论文库条目）均为用户级作用域，不涉及 LLM 或 Embedding 调用，完全由确定性 Python 代码完成。
2. 论文库列表使用 LEFT JOIN 关联可选的 `paper_library_entries`，未加入论文库的论文仍可浏览，条目字段为 null。
3. 高亮使用 `source_hash`（页面文本 + 偏移量的 SHA-256）做防篡校验；服务端从 `normalized_text_content` 和 `char_start/char_end` 派生 `quoted_text`，客户端不得提交任意引用文本。
4. 笔记的 `anchor_type` 为 PAGE / HIGHLIGHT 二选一，由 CHECK 约束强制互斥；知识卡的 `source_note_id / source_highlight_id` 同样二选一。
5. 删除被引用的高亮时返回 409（NOTE_OR_CARD_REFERENCES），不级联删除笔记或知识卡。
6. 阅读进度通过串行 PATCH 调用更新，前端保证同一论文同一时刻最多一个在途进度请求。
7. 016 Alembic 迁移新增 5 张表、4 个枚举和相应约束；非空表 downgrade 在 DDL 前无损中止。
8. 码道收口后，高亮颜色固定为 YELLOW/GREEN/BLUE/PINK，知识卡掌握状态固定为 NEW/LEARNING/MASTERED；高亮与书签重复创建均返回既有对象和 200。
9. 论文库查询使用相关计数子查询避免逐论文 N+1；默认 TO_READ/favorite=false 过滤仍包含尚无 library entry 的论文，且列表读取不写库。

## 19. P8.1 完整管理员系统与不可变审计决策

1. 审计日志采用 append-only 设计，PostgreSQL trigger 在数据库层拒绝 UPDATE 和 DELETE，应用层和数据库层双重保证不可变性。
2. 首个管理员通过 `python -m paperlens.cli admin-bootstrap` CLI 创建，仅在零 ACTIVE ADMIN 时允许执行；不提供默认管理员账号或硬编码凭据。
3. 管理员角色/状态变更使用 `SELECT ... FOR UPDATE` 锁定当前管理员集合，确保至少保留一个 ACTIVE ADMIN；并发降级或禁用导致零管理员时返回 409。
4. 相同值变更（如角色未实际改变）为 no-op，不写入审计日志，直接返回 200。
5. 会话撤销与角色/状态变更在同一事务内完成，确保降级或禁用后旧令牌立即失效。
6. 管理员 API 统一放在 `/api/v1/admin/` 前缀下，通过现有 `require_admin` 依赖做服务端鉴权。
7. 跨用户只读治理（论文/任务/报告）使用列投影，只返回管理员可见字段，不使用 deferred columns 或延迟加载。
8. 审计日志的 `before_state` 和 `after_state` 仅记录 role 和 status 变更，不记录密码、令牌或其他敏感字段。
9. 管理员写操作使用 PostgreSQL 事务级 advisory lock 串行化首次引导与管理员集合变更；取得锁后必须重新读取并校验操作者权限，避免认证完成后权限被并发撤销。
10. 历史 `promote-admin --email` 无审计入口由 P8.1 的 `admin-bootstrap --user-id --reason` 完全替代，防止绕过首次管理员、会话撤销和不可变审计约束。
11. 码道实现轮次负责编写或更新测试，但不执行测试、构建、迁移往返、Docker 重建或 HTTP 烟测；这些命令在交付后的集中验收阶段统一执行。

## 20. 轻量测试策略决策

1. PaperLens 是个人学习项目，不以企业级覆盖率、全故障矩阵或大规模参数组合为目标；测试服务于核心功能可用性，不追求样例数量。
2. 新功能默认只新增 1 个正常路径、1 个重要失败路径；只有真实存在并发、恢复或数据破坏风险时，再增加至多 1 个对应样例。
3. 默认验收只运行本轮变更模块的定向测试、1 条核心烟测和必要构建；不再每轮运行约千项后端全量。
4. 现有测试资产不批量删除，可在最终发布或认证、迁移链、共享基础设施高风险变更时按需运行全量。
5. 不设覆盖率百分比、用例数量增长或全枚举排列门槛；避免重复断言、相同错误码的多组等价样例和大数据生成。

## 21. P8.2 全链路恢复与一致性决策

1. P8.2 新增 RecoveryService，在 FastAPI lifespan 启动时只扫描超过阈值的非终态记录；扫描事务使用 PostgreSQL `pg_try_advisory_xact_lock` 非阻塞互斥，只做有限行锁、状态收口和派发登记，不进行 PDF、模型、文件或报告处理。
2. 可从现有持久化输入完整重放的指标、实验分析、学习解释和论文问答任务重新派发，复用各模块原子 claim；未持久化原始请求参数的审阅、没有可靠执行代次的论文解析和未持久化生成 bytes 的导出统一进入固定公开 FAILED，由用户从原入口重试，不猜测缺失输入。
3. 前端审阅、指标、实验、导出、学习解释、问答和论文解析轮询统一使用共享 `usePolling`，保证单一在途请求、generation 隔离、卸载清理、401 登录跳转和安全错误文案。
4. 为恢复实验分析页面，既有任务详情响应只新增可空 `experiment_file_id` 白名单字段，不新增路由，不公开文件路径、哈希或内容。
5. P8.2 状态：已完成并经码道独立收口；后端 3 passed、前端 2 passed、生产构建 140 modules、隔离健康接口 200，浏览器手工清单留待发布前执行。

## 22. P8.3 性能、可靠性、限流与可观测性决策

1. 请求追踪只复用规范小写 UUID4；非法值重新生成。请求结束日志只记录 request_id、method、路由模板、status、duration_ms 和 rate_scope，未匹配路由统一记 `<unmatched>`，不记录原始路径或查询。
2. 限流采用线程安全、有限容量的单进程固定窗口；健康端点豁免，认证/上传/读取/写入分组集中分类。它不是多实例总限流，P8.4 再由华为云入口层补齐。
3. 默认只相信 TCP peer；仅 peer 命中显式 `PAPERLENS_TRUSTED_PROXY_CIDRS` 时解析严格 X-Forwarded-For 链。原始 IP 只作为内存 key，不写日志。
4. 现有 `/health` 保持兼容，新增 live/ready；ready 只做数据库 `SELECT 1`。数据库池参数有界，恢复派发使用 lifespan 管理的 ThreadPoolExecutor。
5. 不新增迁移或页面。审阅和问答列表消除 N+1，任务列表保留最近 200 条安全上限；Evidence 列表为避免静默丢失论文证据保持原契约，不添加固定截断。
6. P8.3 已完成并经码道独立收口：3 个 P8.3 定向样例、2 个查询回归样例和 1 条隔离 HTTP 烟测通过。

## 23. P8.4 华为云生产化决策

5. ECS 仅发布前端 8080 给 ELB，backend 只在 Compose 私网开放；两类镜像均非 root、只读根文件系统和最小能力集。
6. RPO/RTO 只记录经用户确认并演练的结果，不写未经验证的固定承诺。P8.4 已完成本地轻量生产验收，真实华为云验收待部署窗口执行。

## 24. 论文学习报告导出决策

1. 导出目标由“审阅结果归档”调整为“个人论文学习归档”，报告名称统一为“论文学习报告”。
2. 论文达到 `PARSED` 即可导出，成功审阅不再是前置条件；不存在审阅时仍必须正常生成报告。
3. 学习解释、黄色高亮和笔记是报告的核心学习内容，按页码和创建顺序稳定排列；选中文字解释必须保留原选中文本。
4. 已存在的审阅结果自动作为可选扩展章节加入；指标和实验分析继续由用户显式选择，缺少对应数据时以空状态说明而非阻断导出。
5. Markdown、PDF、DOCX 使用同一份确定性内容快照，快照必须覆盖本用户的解释、高亮、笔记以及实际加入的扩展来源，禁止混入其他用户数据。

## 25. 学习解释退出交互决策

学习解释模块的“退出”不再离开论文工作台或跳转论文库。按钮移动到“生成学习解释”下方；点击后关闭当前解释详情、清除原文蓝色定位并回到同一模块的解释历史列表，保留当前论文和页码。
