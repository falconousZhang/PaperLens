# PaperLens 产品需求文档

## 1. 用户角色

| 角色 | 描述 |
|------|------|
| 研究者（Researcher） | 需要审阅论文、提取实验指标、对比实验结果的科研人员 |
| 审稿人（Reviewer） | 需要快速生成结构化审稿意见的学术审稿人 |
| 实验分析师（Analyst） | 需要从论文和实验数据中提取、汇总、对比指标的数据分析人员 |
| 平台管理员（Administrator） | 负责用户、权限、论文任务、系统运行状态和审计记录管理的运维人员 |

## 2. 使用场景

### 场景一：论文审阅辅助
研究者上传一篇 PDF 论文，系统自动解析章节结构，检索原文证据，生成结构化审阅报告（含优缺点、改进建议），每条结论均绑定原文 Evidence。

### 场景二：实验指标提取与汇总
研究者上传论文后，系统自动从表格和正文中提取实验指标（accuracy、F1、BLEU 等），识别 final/max/mean/best checkpoint 统计口径，生成结构化指标记录。

### 场景三：实验数据文件分析
研究者上传 CSV/Excel 实验数据文件，系统解析数据列，自动识别指标列与条件列，计算统计摘要，与论文中报告的指标进行交叉验证。

### 场景四：审稿报告导出
研究者将审阅结果、指标记录、实验分析汇总为一份完整报告，导出为 Markdown / PDF / DOCX 格式。

### 场景五：用户账号与个人空间
用户注册、登录并维护个人资料，在独立空间中访问自己的论文、审阅任务、实验分析和导出报告；支持安全退出、令牌刷新、密码修改与找回。

### 场景六：管理员运营与审计
管理员通过独立后台查看运行概况，管理用户与角色，处理禁用账号和异常任务，并对受控的数据管理操作形成不可抵赖的审计记录。

## 3. 核心痛点

1. **人工审稿耗时**：阅读一篇论文并撰写审稿意见通常需要 2-4 小时，大量时间花在定位原文证据上。
2. **指标口径混乱**：论文中实验指标常以 final/max/mean/best 等不同口径报告，人工难以快速识别和统一对比。
3. **表格提取困难**：PDF 中的表格结构复杂，复制粘贴后格式错乱，手工转录易出错。
4. **实验数据与论文不一致**：论文报告的指标与原始实验日志之间可能存在偏差，缺乏自动化的交叉验证手段。
5. **审稿意见缺乏依据**：AI 生成的审稿意见常出现幻觉，无法追溯到论文原文，可信度低。

## 4. MVP 功能

### P0 - 必须实现

| 编号 | 功能 | 描述 |
|------|------|------|
| F01 | 论文上传 | 支持 PDF 文件上传（multipart 流式上传），文件类型校验，大小限制 50MB |
| F02 | PDF 解析 | 提取文本、页面信息，识别章节结构（仅支持包含可提取文本的 PDF） |
| F03 | 表格提取 | 从 PDF 中提取表格并结构化存储 |
| F04 | 文本分块 | 按语义段落/章节对论文文本进行分块 |
| F05 | 向量索引 | 对文本块进行 Embedding 并建立向量索引 |
| F06 | 原文证据检索 | 基于问题/关键词检索相关文本块，返回 Evidence（含 PDF 精确定位） |
| F07 | 结构化论文审阅 | 生成包含优缺点、改进建议的审阅结果，每条 Finding 绑定 Evidence |
| F08 | 实验指标提取 | 从表格和正文中提取实验指标，记录指标名、值、数据集、模型名 |
| F09 | Checkpoint 口径判断 | 识别 final/max/mean/best 等统计口径并标注 |
| F10 | 审稿报告导出 | 导出 Markdown 格式的审稿报告 |
| F21 | 用户账号与权限 | 完整注册、登录、退出、令牌刷新、密码修改/找回、个人资料、账号状态和 USER/ADMIN RBAC |
| F22 | 管理员系统 | 管理仪表盘、用户与角色、论文/任务/审阅/报告管理、异常处理和管理员操作审计 |

### P1 - 应该实现

| 编号 | 功能 | 描述 |
|------|------|------|
| F11 | CSV/Excel 实验数据分析 | 上传 CSV/Excel 文件，解析数据列，计算统计摘要 |
| F12 | 指标交叉验证 | 对比论文报告指标与实验数据文件中的指标，标记偏差 |
| F13 | PDF/DOCX 报告导出 | 支持导出为 PDF 和 DOCX 格式 |

## 6. 非目标功能

| 项目 | 说明 |
|------|------|
| 论文自动投稿 | 不涉及投稿流程 |
| 论文写作辅助 | 不涉及论文撰写或润色 |
| 学术搜索引擎 | 不构建论文检索引擎 |
| 实时协作编辑 | 不支持多人实时编辑审阅报告 |
| 论文查重 | 不提供查重服务 |
| 模型训练平台 | 不提供模型训练能力，仅使用 ModelArts 推理接口 |
| 通用文档问答 | 不做通用文档问答，聚焦学术论文审阅场景 |
| 扫描型 PDF / OCR | MVP 仅支持包含可提取文本的 PDF，扫描型 PDF 和 OCR 放入后续版本 |
| 分片上传 | MVP 使用普通 multipart 流式上传，暂不实现分片上传 |

## 7. 约束与原则

1. **所有审阅结论必须绑定 Evidence**：系统生成的每条审阅意见（ReviewFinding）必须关联到论文原文的具体片段（Evidence），不允许无依据的结论。
2. **大模型不直接计算统计数据**：所有数值统计（mean、max、std 等）由确定性 Python 代码计算，大模型仅负责语义理解和文本生成。
3. **文件安全**：上传文件必须经过类型检查、大小限制、路径穿越防护。
4. **用户数据隔离**：不同用户的论文和审阅结果严格隔离。
5. **数据留存策略**：论文原文和分析结果在用户删除或超期后自动清理。
6. **LLM 可替换**：LLM 必须通过统一 LLMClient 接口调用，默认提供 MockLLMClient，使项目没有云端密钥也可以完整演示；需要时可配置 HuaweiMaaSLLMClient，但真实云端可用性以用户开通环境为准。
7. **任务进度通知**：MVP 使用 HTTP 轮询，暂不实现 WebSocket。
8. **认证与授权**：密码必须使用可靠自适应哈希；访问令牌短时有效，刷新令牌轮换并可撤销；所有业务资源按真实用户隔离，管理员权限使用服务端 RBAC 校验。
9. **管理员最小权限**：后台与普通用户界面分离；敏感管理操作必须记录操作者、对象、时间和结果；不得提供硬编码默认管理员密码，首个管理员通过受控初始化流程创建。
